# 원본 대조 검수 방식 (모든 이식 공통)

판본마다 도구는 각자 쓰던 것을 그대로 쓴다. 아래 순서와 기준만 맞춘다. 정해진 날: 2026-11-27(태우).

**공략을 먼저 본다(태우, 2026-11-27).** 정답 경로, 엔딩 조건, 숨은 요소 해금 조건은 공략에서 가져와 입력 목록으로 바로 돌린다. 공략이 없거나 애매한 곳만 전수 탐색이나 롬 분석으로 메운다. 다른 기종의 공략은 해당 판본에서 맞는지 확인한 뒤 쓴다.

## 1. 원본 기록을 먼저 100% 만든다

- 원본은 헤드리스 에뮬레이터에서 실제 패드 입력으로만 움직인다. 램에 값을 써서 진행을 바꾸지 않는다. 읽기는 괜찮다.
- 롬·디스크 판본(헤더 버전, 해시)을 기록 맨 위에 적는다. 이식 기준 판본과 다르면 시작 전에 확인한다.
- 모든 선택지를 갈래별로 돌려 엔딩과 해금(책갈피, 숨은 시나리오)을 전부 모은다. 같은 위치에 같은 상태로 다시 도착한 갈래는 한 번만 돈다. 상태는 플래그·변수·경로 마스크다.
- 기록에는 정지 지점마다 아래를 남긴다. 본문 글자는 남기지 않는다.
  - 대본 위치(뱅크·리소스+오프셋 또는 라벨)
  - 고른 번호
  - 플래그·변수
  - 엔딩 기록

## 2. 체크포인트에서 시작한다

- 정지 지점(선택지·이름 입력)마다 저장 상태를 남긴다. 다음 갈래는 가장 가까운 저장 상태에서 시작한다. 처음부터 다시 재생하지 않는다.
- 회차를 이어 가는 판본은 회차 끝의 세이브를 남긴다. 게임이 직접 쓴 세이브 램을 쓴다.
- 완료 세이브(100%)를 하나 만들어 두면 대부분의 숨은 요소 검수가 여기서 바로 시작된다.
- 특정 지점으로 갈 때는 경로를 다시 밟지 않는다. 게임에 있는 이동 기능(플로차트, 장 선택)을 패드로 써서 바로 간다. 예: PS1 플로차트 노드 BFS.

## 3. 병렬로 돌린다

- 서로 독립인 갈래와 입력은 코어 수만큼 프로세스를 나눠 동시에 돌린다. 프로세스마다 에뮬레이터 하나를 둔다.
- 오래 걸릴 일은 시작 전에 예상 시간을 말한다. 시작한 뒤에는 대표 몇 개를 먼저 끝까지 돌려 방식이 맞는지 확인한 다음 전체를 돌린다.

## 4. 상태로 비교한다

- 이식 쪽은 원본 기록의 경로를 그대로 재생한다. 정지 지점마다 위치·플래그·변수·엔딩을 원본과 대조한다. 이식 엔진을 화면 없이 돌리면 빠르다(예: GBA qa-campaign.mjs).
- 차이는 끝까지 돌린 뒤 한 목록으로 모은다(재생, 단계, 위치, 항목, 원본 값, 이식 값). 하나 고치고 다시 돌리는 핑퐁을 하지 않는다.
- 화면 비교는 상태로 차이를 볼 수 없는 대표 지점에서만 한다. 예: 타이틀, 메뉴, 선택지 상자, 이름 입력판, 책장, 엔딩 목록.

## 5. 표와 판정은 롬에서 읽는다

- 이름 표, 엔딩 제목, 메뉴 문자열, 판정 분기는 롬·실행 파일에서 직접 뽑는다. 이식 데이터의 표와 글자 단위로 비교한다.
- 실제 입력은 판정 갈래마다 대표 한두 개와 경계 사례만 넣는다. 예: 표에 없는 이름, 호칭 변형, 별명.
- 입력 전에 입력 칸이 비어 있는지 화면이나 램으로 한 번 확인한다. GBA 이름 칸에는 「あ」가 미리 들어 있었다.
- 입력 직후 판정 결과가 상태에 안 보이고 나중에 쓰이는 경우가 있다. 이때는 판정 명령이 쓰는 변수를 읽거나, 판정 분기 직후 위치를 본다.

## 6. 숨은 요소 목록을 대조한다

- 판본마다 기준 목록을 만든다: `qa/<작품>-<기종>-beta/hidden/hidden-elements-*.md`. 공략 자료와 롬 분석으로 후보를 모으고, 원본에서 확인한 것만 "확인함"으로 적는다.
  - 대상: 숨은 시나리오, 숨은 메뉴·커맨드, 이스터 에그, 해금 보상
- 원본에 있는 것은 이식에도 있어야 한다. 넣지 않기로 태우가 정한 것만 "제외"로 적는다. 예: SFC 2P 데이터 삭제 커맨드.
- 이식 결과는 항목마다 "있음 / 없음 / 다름 / 제외"로 같은 문서에 적는다.

## 7. 보고

- 줄거리와 정답(범인 등)은 쓰지 않는다.
- 남길 것: 판본, 돌린 범위(엔딩 수, 선택지 수, 입력 수), 차이 목록, 남은 확인, 걸린 시간.
- 저장 위치: 기록·결과 JSON과 스크립트는 `qa/<작품>-<기종>-beta/`. 롬, 디스크 이미지, BIOS, 세이브, 저장 상태는 커밋하지 않는다.
