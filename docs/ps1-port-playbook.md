# PS1 사운드노벨 웹 이식 작업 지침 (카마이타치 특별편에서 얻은 것)

카마이타치의 밤 특별편(PS1)을 웹으로 옮기면서 맞았던 방법과 돌아간 길을 정리했다. 다음 PS1 이식(첫 대상: 마녀들의 잠 PS1판)은 이 순서대로 진행한다. 게임 대사, 디스크 바이트, EXE 바이트는 이 문서와 공개 저장소에 넣지 않는다.

공통 규칙은 [CONTRIBUTING.md](../CONTRIBUTING.md), 원본 대조 검수 순서는 [docs/qa-method.md](qa-method.md)를 따른다.

## 0. 목표와 하지 말 것

- 목표는 **원본 그 자체의 웹 재현**이다. 원본의 실행 루틴을 JS로 옮겨 같은 화면·타이밍·소리·분기를 낸다. 대사만 띄우는 새 플레이어나 캡처 화면 재생은 하지 않는다.
- 웹판은 디스크·BIOS·원본 롬 없이 실행된다. 런타임은 사용자 디스크에서 미리 뽑은 **비공개 포트 데이터**(장면 레코드, 그림, 소리, EXE 데이터 구역)만 읽는다. 포트 데이터는 공개 저장소에 커밋하지 않는다.
- 화면은 원본 기능까지 동작해야 끝난 것이다. 예: 메모리 카드 화면은 실제 저장·불러오기·이어하기까지. 원본의 로딩용 검은 화면은 웹에서 줄여도 된다(`?timing=original`로 원본 타이밍).
- 한글은 웹판 전용이다. 패치 롬·패치 디스크는 만들지 않는다.

## 1. 첫날: 판본 고정과 대사 추출 (번역을 바로 병렬로 시작)

번역이 가장 오래 걸리므로 **대사 추출을 엔진보다 먼저** 끝내서 번역 세션에 넘긴다. 엔진 이식은 그 뒤에 나란히 진행한다.

1. 디스크 판본 기록: 파일명, 트랙 구성, SHA-1/SHA-256, `SYSTEM.CNF`의 BOOT EXE 이름과 해시. 원본 파일은 태우 PC `D:\work\Soundnovel project\roms\`에 있다. 원본은 읽기 전용으로만 쓴다.
2. ISO 파일 목록과 아카이브(PAC 등) 색인. 각 멤버의 LBA, 크기, 해시, 압축 방식을 `manifest.json`에 남긴다(특별편: `private-tools/extract-port-data.py`, `psx-analysis/tools/psx_disc.py`, `pac_index.py`).
3. 압축은 추측하지 말고 **EXE의 해제 루틴을 그대로 실행**해서 푼다(특별편: SCE 해제 0x800356c8를 하네스로 실행, LZS는 원본 스트림 규칙 그대로).
4. 시나리오 해석기의 opcode 길이표를 EXE에서 읽고, 레코드를 처음부터 끝까지 선형으로 읽어 **모든 텍스트 명령**을 뽑는다.
   - ID는 `RRR-SSS-OOOO`(리소스-레코드-텍스트 명령 오프셋)처럼 디스크에서 바뀌지 않는 값으로 정한다. 번역, 용어집, 검수 의견이 모두 이 ID에 붙는다.
   - 제어 바이트는 `[r]`, `[p]`, `[n1]` 같은 토큰으로 바꾼다. 토큰 뜻은 형식 문서에 표로 적는다.
   - 선택지 질문과 보기에는 표시(`beforeChoice` 등)를 붙여 번역 때 함께 보이게 한다.
   - **누락 검사**: SJIS 4자 이상 텍스트처럼 보이는 바이트 중 어느 항목에도 안 들어간 것을 `uncovered.json`으로 낸다. 반드시 `[]`이어야 한다.
   - EXE 안의 문자열(메뉴, 카드 화면, 엔딩 제목, 인물 소개, 플로차트 제목)과 이름 판정표도 따로 뽑는다(`extra/`).
5. 형식은 특별편 것을 그대로 쓴다: [ports/kamaitachi-ps1/docs/script-format.md](../ports/kamaitachi-ps1/docs/script-format.md)(파일 `script.ja.json`, 읽기용 `md/RRR.md`, `uncovered.json`). 형식을 바꾸면 이 문서도 함께 고친다.
6. 추출 결과는 그 작품의 **비공개 저장소**에만 커밋하고, 커밋 SHA를 PR 댓글로 알린다. 번역 세션은 이 SHA에서 시작한다.

## 2. 번역 세션으로 넘길 때

- 번역 모델: 초벌 `gpt-6-luna`, 어려운 구간 비교·재벌 `gpt-6.1-terra`(외부 번역 프로그램, CONTRIBUTING.md). 재개 가능한 장면 단위 번역 도구는 `majo-tach-sfc-kor` `tools/translation/`(scene_batch.py)를 쓴다.
- 같은 작품의 다른 판본 번역이 있으면 **같은 문장은 그 번역을 기준본으로** 쓰고, 다른 문장만 새로 번역한다. 인명·용어는 판본 사이에 반드시 같게 한다.
- 출력은 `script/ko/script.ko.json`(`id`, `ko`)와 `extra/*-ko.json`. 제어 토큰의 철자·개수·순서는 원문과 같아야 한다.
- 번역 세션이 스스로 돌리는 자동 검사: ID 누락·중복, 빈 응답, 제어 토큰 불일치, 일본어 잔존, 용어집 위반, 이름 토큰 뒤 조사. 그다음 **이름을 채운 실제 표시 문장으로 전체 정독**(오탈자·띄어쓰기·누락·오역, 말장난과 수수께끼 성립 여부). 패턴 치환만으로 끝내지 않는다.
- 태우가 정한 공통 표기: 단위가 붙은 수는 숫자(1층, 30대, 12시), 고유어 수 세기는 한글(쉰 살, 두 사람). 간사이벤 화자는 진한 경상도 사투리(서술은 표준어). 작품별 결정은 그 작품 용어집에 적고 다시 묻지 않는다.
- 끝나면 Claude가 독립 검수를 한 번 더 한다(번역한 세션이 아닌 다른 눈).

## 3. 엔진: 원본을 헤드리스로 돌리는 "오라클"부터

특별편에서 가장 효과가 컸던 순서다.

1. **원본 전체 헤드리스 부팅**(오라클): R3000A 해석기 + GPU 모델 + SPU 모델로 사용자 EXE를 엔트리부터 실행한다. 라이브러리 서비스(libcd, VSync, 패드 버퍼, 메모리 카드, STR)만 HLE로 둔다. 특별편: `tools/oracle/game-boot.mjs`, `mips.js`, `gpu-oracle.mjs`.
2. **이식은 루틴 단위**로 한다. VSync를 기다리는 루틴은 JS generator로 옮겨 `yield`를 VSync(0)로 쓴다. 그러면 브라우저 프레임 루프와 오라클 대조가 같은 코드를 쓴다.
3. 이식할 때마다 **원본과 프레임 단위로 대조**한다(GP0 명령, 화면, RAM). 특별편: `tools/oracle/compare-screen.mjs <dir> N --ports …`. 무입력 수만 프레임과 기본 입력 수만 프레임이 원본과 같아야 다음으로 간다.
4. 손으로 옮기기 긴 메뉴·특수 화면 코드는 **MIPS → JS 명령어 단위 자동 변환**을 쓴다(`tools/translate/gen-menu.py`, capstone). 손 이식 루틴과는 `calls.js`로 잇는다.
5. 시나리오 해석기는 opcode 전체를 한 번에 구현하고, 미구현은 주소를 남기고 멈추게 한다. 한 장면씩 핑퐁하지 않는다.
6. 사운드: libsnd/libspu 루틴과 게임 사운드 모듈을 JS로 옮기고(AudioWorklet), 원본 루틴을 오라클에서 돌려 **SPU 레지스터 쓰기 로그를 한 줄씩 비교**한다. 곡·효과음 전체를 자동 렌더해 확인한다(특별편 73곡·301효과).
7. EXE의 데이터 구역(사인표, 글꼴 해시 등)은 코드가 아니라 포트 데이터로 적재한다(`extract-exe-data.mjs`).

### 특별편에서 실제로 걸렸던 것

- 원본이 남은 레지스터(a1 등)를 인자로 그대로 넘기는 호출이 있다. 이식 함수 시그니처를 원본 레지스터 사용에 맞춘다.
- 오라클과 이식 코드를 섞어 돌리면 스택이 겹쳐 메뉴에서 거짓 차이가 난다. 메뉴는 "이식 머신 vs 무이식 원본" 비교를 기준으로 한다.
- 정적 서버는 gzip 응답을 줄 수 있다. 포트 데이터 로더가 둘 다 받게 한다.
- 메모리 카드는 원본 형식(128KB .mcr)으로 가상화하고, **빈 카드로 시작**해 원본의 "데이터 없음 → 만들기" 흐름이 실제로 돌게 한다. 카드 읽기 대기도 원본처럼 "읽는 척"한다.
- 고정 x 좌표에 조각을 찍는 명령(특별편 0x18)이 있으면, 한글 조각이 원래 칸 폭 안에 들어가는지 빌드마다 검사한다(`tools/ko/fixed-x-check.mjs`).

## 4. 한글 표시

- 원본 글꼴 형식으로 한글 글리프를 만들어 원본에 없는 코드 영역에 넣는다(특별편 `tools/ko/build-ko.py`: 12px 래스터, 원본 가나보다 1px 작게, 공백 폭 6, 원본과 같은 줄 수).
- 이름 토큰 뒤 조사는 표시할 때 받침을 보고 고른다(`src/text/josa.js`).
- 빌드 보고서에서 화면 넘침 0건, 고정 위치 조각 검사 통과를 확인한다. 새 글자가 생기면 글꼴을 다시 만든다(글꼴 파일 위치를 저장소 README에 적어 둔다).
- 태우가 대화 편집기로 고친 문장(owner edits)은 번역 재빌드 때 덮어쓰지 않는다.
- 글꼴 원본 파일(.ttf)은 빌드하는 곳(태우 PC)에 함께 둔다. 특별편은 PC에 글꼴이 없어 새 글자가 생기면 재빌드할 수 없었다. 위치를 README에 적는다.
- 번역 입력(본문·EXE 문자열·판정표)은 **한 브랜치의 한 커밋**에서 빌드한다. 특별편은 EXE 문자열 수정이 다른 브랜치에만 있어 재빌드 때 되돌아갈 뻔했다.

## 5. 웹 셸 연결

공통 부품을 그대로 쓴다. 새로 만들지 않는다.

- 시작 관문과 새로하기/이어하기: `shared/player/start-gate.js`, `start-choice.js`
- 터치만으로 모든 선택(패드 없음): 선택 루프마다 터치 행(`touchRows`)을 제공해 행을 누르면 바로 그 행으로 가고 결정한다.
- 저장: 게임 안 저장(가상 메모리 카드)과 이어하기 지점이 같은 6자리 코드에 자동으로 올라간다(`shared/save/quick-save.js`, `sync-ui.js`).
- 신고 버튼: `shared/player/report-button.js`. 포트는 `globalThis.soundnovelReport = () => ({ scene, text })`를 제공한다.
- 화면 오른쪽 아래 아이콘 순서: 플로우차트(메뉴) / 저장 / 신고.

## 6. 검수 (QA-METHOD.md 순서 그대로)

1. 공략을 먼저 본다. 정답 경로, 엔딩 조건, 숨은 요소 해금 조건을 공략에서 가져와 입력 목록으로 바로 돌린다.
2. 원본 기록 100%: 헤드리스 에뮬레이터, 패드 입력만, 선택지마다 저장 상태(체크포인트), 독립 갈래는 병렬, 상태(위치·플래그·변수·엔딩)로 비교. 화면 비교는 대표 지점만.
3. 이름 판정표·엔딩 제목·메뉴 문자열은 EXE에서 읽어 이식 데이터와 글자 단위로 대조한다. 실제 입력은 대표값과 경계값만 넣는다.
4. 숨은 요소 목록을 따로 만들어 이식에 모두 있는지 확인한다.
5. 이식 쪽은 원본 경로를 화면 없이 재생해 차이를 한 목록으로 모은다. 하나씩 고치며 다시 돌리지 않는다.

## 7. 일하는 방식

- 오래 걸릴 일은 시작 전에 더 빠른 방법(체크포인트, 병렬, 상태 비교, 표를 롬에서 읽기)을 먼저 찾고, 예상 시간을 말한다.
- 태우 PC에서는 창을 띄우지 않는다. 원본 에뮬레이터 화면 기록은 클라우드 헤드리스로 한다.
- 롬·디스크 이미지·BIOS·세이브·저장 상태는 커밋하지 않는다.
- 보고는 단계가 끝날 때만, 담당 PR에 중간보고 댓글로 남긴다: 커밋 SHA, 범위, 자동 검사 결과, 남은 일. 줄거리와 정답은 쓰지 않는다.
- 유료 API는 작은 표본으로 비용을 재고, 한 단계 비용이 10달러를 넘을 것 같으면 먼저 묻는다.
