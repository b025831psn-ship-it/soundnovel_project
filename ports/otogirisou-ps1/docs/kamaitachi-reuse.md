# 카마이타치 PS1 재사용 판정

카마이타치 PS1 포트의 결과물은 중요한 선행 자산이지만, 제절초가 같은 회사의
작품이라는 이유만으로 같은 엔진이라고 확정하지 않는다. 제절초 디스크의 실행
파일을 확보한 뒤 아래 순서로 모듈별 재사용 여부를 판정한다.

## 판정 단위

| 영역 | 우선 확인할 근거 | 판정 후 처리 |
|---|---|---|
| SPU·음원 모듈 | SPU 레지스터 초기화 순서, DMA 루틴, 음원 헤더·시퀀스 구조, XA 사용법, 호출 그래프 | 동일하면 공용 모듈, 파생이면 어댑터, 다르면 제절초 전용 구현 |
| 메모리 카드 | BIOS 호출 조합, 블록/디렉터리 형식, 저장 헤더, 체크섬, 슬롯 UI 호출 관계 | 저수준 I/O와 작품별 저장 형식을 분리 |
| 글자 그리기 | 폰트 적재 주소, 문자 인코딩, 글리프 전개 루프, GP0 패킷, CLUT·VRAM 배치 | 래스터/업로드 코어와 폰트·레이아웃 자료를 분리 |
| 시나리오 VM | 디스패처 지문, opcode 표, 상태 구조, 점프·조건·선택지 표현 | 표와 상태 구조가 일치할 때만 실행기 공유 |
| 컨테이너 | 인덱스 엔트리 크기, 정렬, 압축 표식, 레코드 경계 | 탐지기는 공유하되 파서는 형식 확인 후 연결 |

판정값은 다음 셋만 사용한다.

- `identical`: 함수와 자료 구조가 대조 범위에서 같아 공용 코드로 추출할 수 있다.
- `derived`: 구조는 같지만 주소·상수·표·일부 루틴이 달라 작품별 어댑터가 필요하다.
- `distinct`: 같은 인터페이스를 강요하면 원작 동작을 왜곡하므로 별도 구현한다.

함수 이름이나 육안상 비슷한 화면은 근거로 쓰지 않는다. 실행 파일 해시가 달라도
함수 바이트·정규화된 명령열·호출 관계·동적 이벤트가 함께 맞으면 재사용 후보가
될 수 있다. 반대로 SDK 공통 함수만 같고 게임 상태 구조가 다르면 엔진 동일성의
근거가 아니다.

## 가장 먼저 재사용할 도구

엔진 동일성 판정 전에도 다음 도구 계층은 재사용 효과가 크다.

1. **자동 인벤토리·변환 기반**
   - CUE/BIN 파일 해시, 트랙, ISO9660, SYSTEM.CNF와 PS-X EXE 헤더 조사
   - PS1 VRAM/CLUT 변환, GP0 패킷에서 VRAM 상태 복원
   - 변환 자산에 원본 위치·해시·변환기 버전을 붙이는 매니페스트
2. **원작 대조 기반**
   - GPU 프록시와 CPU/CD/GPU/SPU/VBlank/입력 이벤트 JSONL 정규화
   - 원본 추적과 웹 실행 추적의 첫 불일치 탐색
   - 합성 fixture 및 화면 체크포인트 비교

카마이타치의 PAC 인덱서, 시나리오 opcode 해석, 주소표는 제절초 형식이 확인된
뒤에만 연결한다. 범용 PS1 계층은 복사본을 늘리지 않고 공용 코어로 추출하고,
작품별 값은 `kamaitachi`와 `otogirisou` 어댑터에 둔다.

## 비교 절차

1. 양쪽 기준 판본과 PS-X EXE의 SHA-256, 적재 주소, 엔트리 주소를 기록한다.
2. import/BIOS 호출, 문자열·SDK 표식, 점프 테이블, MMIO 참조를 기계적으로 뽑는다.
3. 주소를 제거해 정규화한 함수 지문으로 후보를 만들고 호출 그래프로 오탐을 줄인다.
4. SPU, 메모리 카드, 글자 그리기 후보를 원본 실행에서 각각 한 경로 이상 추적한다.
5. 입력이 같은 구간의 외부 효과와 상태 전이가 맞을 때만 `identical`로 올린다.
6. 판정 근거, 비교 도구 버전, 미확인 경로를 비공개 분석 기록에 남긴다.

## 완료 조건

- 세 영역(SPU·메모리 카드·글자 그리기)에 판정값과 정적·동적 근거가 있다.
- 자동 변환 결과가 같은 입력에서 결정적이며 원본 위치까지 역추적 가능하다.
- 원작 대조 도구가 의도적으로 바꾼 합성 이벤트의 첫 불일치를 정확히 찾는다.
- 작품별 상수나 원본 자료가 공용 코드와 공개 fixture에 섞이지 않는다.
