# 작업 방식과 검증 게이트

## 선행 작업에서 채택한 원칙

상위 협업 규칙, `otogirisou-sfc-kor`, `kamaitachi-ps1-kor`, 그리고 공개
SFC 포트 문서를 대조했다. 다음만 재사용하고 작품별 사실은 새로 확인한다.

- 재사용: 공개/비공개 데이터 경계, 읽기 전용 원본, 해시 기반 판본 고정,
  합성 fixture, 네이티브 추적과 웹 실행의 첫 불일치 비교, 고정 ID 기반 번역.
- 새로 분석: 디스크 ID와 트랙 구성, 실행 파일 주소, 아카이브 형식, 스크립트
  opcode, 글꼴, GPU/SPU/XA/STR 사용법, 세이브 구조와 분기 조건.
- 사용하지 않음: SFC판 주소·opcode·분기표, 다른 작품의 화면 녹화값, 다른
  작품에 맞춘 이름 입력이나 시나리오 가정.

## 단계별 게이트

1. **판본 고정**
   - CUE가 참조하는 모든 파일의 크기와 SHA-256을 기록한다.
   - 트랙 모드, 섹터 크기, INDEX 위치, SYSTEM.CNF와 부팅 실행 파일을 확인한다.
   - 매니페스트 검증을 통과하기 전에는 주소 분석 결과를 정본으로 기록하지 않는다.
2. **원본 기준선**
   - 깨끗한 메모리 카드 상태와 입력 순서를 기록한다.
   - 부팅부터 첫 선택지까지 CPU/CD/GPU/SPU/입력 이벤트의 안정 필드를 정한다.
   - 에뮬레이터·플러그인·BIOS/HLE 조건과 관찰 한계를 함께 기록한다.
3. **구조 인벤토리**
   - 파일/아카이브/스크립트 경계를 먼저 계수하고, 알려지지 않은 바이트를 보존한다.
   - opcode는 명령 경계와 동적 디스패치 근거가 있을 때만 이름을 붙인다.
   - 텍스트의 ID는 파일·레코드·명령 위치에서 결정적으로 생성하고 번역 때문에
     바꾸지 않는다.
4. **최소 실행기**
   - 합성 데이터로 파서의 경계값, 잘림, 중복 ID, 잘못된 참조를 먼저 시험한다.
   - 첫 수직 슬라이스에 실제로 도달한 명령과 장치 동작만 구현한다.
   - 원본과 첫 불일치가 생기면 우회하지 않고 원인과 근거를 기록한다.
5. **웹 자산과 런타임**
   - 추출 단계에서 웹용 무손실 기준 자산과 출처 ID를 만든다.
   - 웹 런타임은 원본 매체 없이 같은 상태 전이·화면·소리를 재생한다.
   - 개발 UI는 원작 화면 바깥에 두고 원해상도 정수 배율을 기본으로 한다.
6. **한글화**
   - 도입부 서술·대사·선택지 표본으로 문체, 글꼴, 줄바꿈을 먼저 검증한다.
   - 전체 원문과 제어 코드가 추출된 뒤 고정 ID 단위로 초벌·독립 검수·재벌을 한다.
   - 누락/중복 ID, 제어 코드, 지원 문자, 분기 도달성과 저장/재개를 자동 검사한다.

## 즉시 차단 조건

- 기준 디스크 파일이 없으면 판본·주소·아카이브 형식을 추정하지 않는다.
- 원본 데이터가 공개 Git 변경에 포함되면 커밋하지 않는다.
- 기존 담당 범위인 허브, 공통 스타일, 공통 세이브는 별도 순서 합의 전 수정하지 않는다.
- 원본 추적과 설명이 맞지 않으면 번역이나 전체 추출로 범위를 넓히지 않는다.
