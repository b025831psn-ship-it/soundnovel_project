# 카마이타치의 밤 2 · PS2 웹 포트

일본 한정판 게임 디스크의 새 게임 경로를 브라우저에서 재생한다. 로고와 타이틀을 거쳐 두 사람의 이름을 정하면, 주인공이 대학 동기였던 여자친구와 스키를 타러 간 일을 회상하는 대목까지 진행한다. HTML 비디오가 영상을 재생하고 Canvas와 JavaScript가 입력·분기·텍스트를 처리한다.

**플레이하는 사람은 웹 주소만 열면 된다.** 제작자가 ISO로 한 번 빌드하면 `web/` 폴더 하나가 독립적인 정적 사이트가 된다. 게임을 제공하는 서버에도 이 폴더만 있으면 된다. 아래 Python·FFmpeg·Ghidra 절차는 제작·검증용이다.

## 실행

Python 3.11 이상과 Pillow, IPU 디코더 및 libx264 인코더가 있는 FFmpeg와 ffprobe가 필요하다. 저장소 루트에서 실행한다. 준비기는 디스크를 읽어서 미디어와 문자표를 로컬 웹 폴더에 생성한다. 브라우저에서는 준비된 폴더만 서비스하면 된다.

```powershell
$iso = (Resolve-Path -LiteralPath 'roms/Kamaitachi no Yoru 2 - Kangoku-jima no Warabe-uta (Japan) (Special Box).iso').Path
python -B ports/kamaitachi2-ps2/prepare.py "$iso" --output outputs/kamaitachi2-ps2-kor/web
python -m http.server 8772 --bind 127.0.0.1 --directory outputs/kamaitachi2-ps2-kor/web
```

[로컬 플레이 화면](http://127.0.0.1:8772/)은 즉시 시작하며 첫 탭이나 키 입력에서 소리를 활성화한다. 일본어 원판의 글꼴과 이름 문자표를 사용한다. 방향키로 이동하고 Enter 또는 Z로 ○, Esc 또는 X로 ×, S로 △를 누른다. Q와 W가 L1과 R1, Space가 START다. 화면 아래의 버튼과 표준 매핑 게임패드도 같은 입력 처리기를 사용한다.

## EE 어셈블리에서 확인한 동작

주소는 실행 파일이 매핑된 EE 가상 주소다. `jal` 직후의 명령도 호출 인자를 설정할 수 있으므로 지연 슬롯을 포함해 확인했다.

로고·저작권 표시·오프닝 재생 중 ○, START 또는 L2를 누르면 타이틀 루프에 직접 진입한다. 웹 키보드에서는 각각 Enter, Space, 숫자 2에 대응한다. 미디어 루틴은 `0x00107D50`에서 마스크 `0x2108`을 검사하고 입력이 있으면 `0x00107D5C`에서 반환할 값을 0으로 설정한다. 호출자는 로고 뒤 `0x00100174`, 저작권 표시 뒤 `0x00100190`, 오프닝 뒤 `0x00100210`에서 이 값을 반영한다. 타이틀은 `0x00108478`에서 진입 플래그가 0이면 루프 영상 경로를 선택한다.

| 위치 | 확인한 동작 |
| --- | --- |
| `0x00100018`, `0x001000A4` | 시작 루프가 R5900의 128비트 `sq`로 메모리를 초기화한다. 초기화 뒤 `0x001532D0`을 호출한다. |
| `0x001648CC` | `0x00168D50`을 호출한다. 지연 슬롯이 `a0`를 디스크 FAD 경로 문자열의 주소로 완성한다. |
| `0x0010016C`, `0x00100188`, `0x00100204` | 로고 PSS, 저작권 IPU, 오프닝 PSS를 같은 미디어 루틴 `0x00107C68`에 전달한다. 저작권 화면의 네 번째 인자는 140이다. `0x00107D50`에서 입력 마스크 `0x2108`을 검사한다. |
| `0x00108470`, `0x00108484`, `0x00108498` | 타이틀 음악의 파일명은 `0x00219C08`에 있다. 타이틀 진입 상태에 따라 MMV 또는 M2V를 연다. MMV의 두 번째 영상은 별도 타이틀 M2V와 바이트 단위로 같다. |
| `0x00108B34`, `0x00108B70`, `0x00108C18` | 타이틀 입력 비트가 있으면 무입력 카운터를 0으로 되돌린다. 선택 결정 마스크는 ○·START·L2에 해당하는 `0x2108`이다. 좌우는 메뉴 범위 안에서 한 칸씩 이동하며, 실제 인덱스가 달라졌을 때만 `0x00108C78`에서 이동음을 호출한다. |
| `0x00131A78`, `0x00131AE4`, `0x00131AEC` | 이름 명령 핸들러가 `0x12`와 `0x13`을 구분한다. SN4 라벨 `my01_0047`, `my01_0062`가 각각 해당 명령으로 끝난다. 입력 상태 진입 호출은 `0x00131B70 → 0x0011B4D0`이다. |
| `0x0011C490` | `NameInputNormal` 버튼 루틴. L1/R1 마스크 `0x0400/0x0800`, ○/×/△ 마스크 `0x2000/0x4000/0x1000`을 검사한다. |
| `0x0011C4D8–0x0011C528` | R1은 마지막 그룹에서 첫 그룹으로, L1은 첫 그룹에서 마지막 그룹으로 순환한다. 전환 직후 현재 열, 보이는 행, 기억한 열, 스크롤 위치를 모두 0으로 초기화한다. 새 게임 글자판에서는 첫 그룹의 `あ`와 마지막 그룹의 전각 `Ａ` 사이를 양방향으로 이동할 수 있다. |
| `0x0011C52C → 0x0011C5F0`, `0x0011CA88` | 방향 입력을 처리할 때 원본은 행당 46바이트를 사용한다. 앞 30바이트는 2바이트 문자 15개이고, +0x1E부터 각 칸의 상태를 검사한다. 좌우 이동에서 경계를 넘거나 공백 표시(0x20)를 만나면 오른쪽 이동은 열 0부터, 왼쪽 이동은 열 14부터 유효한 칸을 찾는다. 위·아래 처리 뒤에도 같은 보정 함수가 호출되며, 모드 3에서는 대상 칸이 비었을 때 오른쪽 끝에서 왼쪽으로 탐색한다. |
| `0x0011C588 → 0x0011BEA0` | 선택한 2바이트 문자를 추가한다. 이름이 이미 12바이트면 마지막 2바이트 위치에 쓴다. 웹에서 일곱 번째 입력은 여섯 번째 글자를 교체한다. |
| `0x0011C5A4 → 0x0011BF58`, `0x0011C5D8 → 0x0011C190` | ×로 글자를 지운다. △에서 빈 이름은 개체에 보관한 초기 이름으로 복원하고 확인창으로 간다. 기본 이름은 EE `0x00224628`, `0x00224630`에서 읽는다. |

동시에 여러 버튼이 눌린 프레임의 처리 순서도 EE 코드에서 확인할 수 있다. `0x0011C4CC`에서 R1을 먼저 검사하며 이 분기가 실행되면 L1 검사를 건너뛴다. 그룹 변경 뒤에도 `0x0011C52C`의 방향 처리 호출을 거친다. 이후 같은 입력값에서 ○(`0x0011C538`), ×(`0x0011C598`), △(`0x0011C5A0`) 순으로 마스크를 검사한다. ○로 문자를 추가하거나 ×로 지우면 함수 끝으로 분기하므로, 한 프레임에 편집 동작은 최대 하나다. 예를 들어 R1과 ○를 함께 누르고 방향 입력이 없으면 새 그룹의 첫 칸 문자를 입력한다. 브라우저 테스트에서는 표준 게임패드의 L1·R1·○·×·△가 같은 프레임에 눌린 상태를 제공해, 이름 편집 화면을 유지하면서 두 번째 그룹의 첫 글자 か만 추가되는 것을 확인한다.

방향 판정 함수 `0x0011BFE8`은 대각선 마스크 0x90, 0x30, 0xC0, 0x60을 차례로 검사한 뒤 단일 방향을 판정한다. 두 점프 테이블(0x0021B060, 0x0021B080)을 거쳐 대각선은 가로 이동 후 세로 이동으로 처리한다. 방향이 바뀌면 즉시 이동하고 반복 카운터를 18로 설정한다. 같은 방향이 유지되면 카운터가 0에 도달할 때 이동하고 6으로 재설정한다(0x0011C098–0x0011C0D4). 웹 게임패드 테스트에서는 か에서 오른쪽을 약 0.42초 누른 뒤 ○를 누르면 세 칸 오른쪽의 ガ가 입력된다. 웹은 59.94Hz 기준 경과 시간으로 반복 시점을 계산한다.

두 기본 이름 입력 화면의 640×480 원본 캡처에서 위아래 16픽셀을 제외한 640×448 영역을 기준으로 패널 경계를 측정했다. 주인공·여자친구 화면 모두 제목 띠는 y=28–63, 글자 그룹 띠는 x=136–503, y=74–105, 키보드 바탕은 x=75–564, y=116–377이다. 좌표는 양 끝 픽셀을 포함한다.

펜션 배경의 정렬은 별도 대조가 필요하다. 위와 같이 자른 두 원본 화면에서 RGB 세 채널이 모두 일치하는 픽셀만 골랐다. 검사 영역은 파이썬 슬라이스 `[8:24,8:-8]`, `[68:382,8:52]`, `[68:382,578:-8]`, `[422:-8,8:-8]`의 합집합이다. 추출한 `my0645.png`에 채널별로 `0.31 × 값 + 6.4`를 적용하고 x 방향 −3~3, y 방향 −6~6픽셀의 정수 이동을 비교하면 평균 절대 오차가 가장 작은 이동은 (−1, −4)이고 오차는 0.912/255다. 개별 영역에서는 최적 이동이 달라진다. 이 측정은 전체 화면의 이동이나 원본의 배율을 확정하지 않는다.

이름 확인 화면에서도 제목 띠는 y=28–63이다. 예·아니오 패널의 바깥 경계는 x=235–372, y=252–323이다. 기본 선택인 아니오 화살표에서 RGB 세 채널이 모두 120을 넘는 픽셀의 경계는 x=249–260, y=297–310이다. 예 위치에는 웹에서 같은 스프라이트를 32픽셀 위에 표시한다.

### 이름 확정 뒤의 분기

`scenario.sn4` 파일 오프셋 `0xB2B33`에서 시작하는 `my01_0070`에는 여자친구 이름을 삽입하는 `0x0E`가 세 번 나온다. 스키 회상 뒤에는 `6C 1B 01 02 00 00 0C`에 이어 `my01_0075`, `my01_0073` 두 목적지가 이 순서로 들어 있다. 각 라벨의 시작 오프셋은 `0xB2CAF`, `0xB2C65`다.

웹 준비기는 `0x6C`의 길이 바이트와 두 목적지의 타입·NUL 종료·구분 바이트를 검사하고, 구체적인 라벨명을 정규식에 하드코딩하지 않고 목적지를 해석한다. 첫 선택지는 기록 순서대로 `my01_0075`와 `my01_0073`을 표시한다. 첫 분기는 `my01_0075 → my01_0076 → my01_0077`을 실행해 `my0002e_10` 장면 전환까지, 둘째 분기는 `my01_0073`의 응답 뒤 `mo01_0000` 점프 직전까지 VM으로 진행한다.

`prepare.py`는 이 구간을 별도의 `assets/sn4.json`으로 생성한다. 각 레코드는 `{label, offset, ops:[{op, offset, args}]}`이며 `offset`은 모두 `scenario.sn4` 파일의 절대 오프셋이다. 현재 일반 경로 범위는 `my01_0047`부터 날짜·여름 재회 장면을 거쳐 `my02_0100`의 다음 선택지까지이며, 회상 분기는 `my01_0073`의 `mo01_0000` 점프 직전까지다. 초대장 `my01_0078–0080`의 여백·글꼴·후리가나·좌표 명령과 저자 소개·전화·여름 장면의 wait도 VM 이벤트로 실행한다. `sn4.js`는 이 JSON을 읽어 이름 명령과 선택·점프를 실행하고, 미구현 opcode는 라벨과 원본 오프셋을 포함한 오류로 즉시 중단한다. 브라우저 검사는 VM을 선택지별로 새로 만들어 각 장면 전환 경계까지 모든 pause와 wait 이벤트를 실행한다. `my02_0100` 선택 뒤 목적지 `my02_0110`/`myb02_0010`은 아직 기존 페이지 생성기로 인계한다.

첫 선택지까지 쓰는 SN4 명령의 초기화 분기표와 피연산자 형식은 다음과 같다. 주소는 `0x0021A240 + 4 × (opcode - 2)`가 가리키는 EE 초기화 핸들러다. 정수는 별도 표기가 없으면 빅엔디언이다.

| opcode | EE 초기화 핸들러 | 피연산자 형식 | 역할 |
| --- | --- | --- | --- |
| `02` | `0x0010F620` | CP932 문자열, `03` 종료 | 본문 |
| `04` | `0x0010F640` | 없음 | 줄바꿈 |
| `09` | `0x0010F660` | 없음 | 입력 대기 |
| `0D` / `0E` | `0x0010F6E0` | 없음 | 주인공 / 여자친구 이름 삽입 |
| `12` / `13` | `0x0010FC40` | 없음 | 주인공 / 여자친구 이름 입력 |
| `16` | `0x0010F700` | 없음 | 표시 상태 구분자(no-op) |
| `40` | `0x0010F7C0` | `u8` | 글자 속도 |
| `46` | `0x0010F940` | `u8` | 자간 |
| `4C` | `0x0010F8C0` | `u8, u8` | 글꼴 인자 |
| `50` | `0x0010FA00` | `u32` | 갱신 횟수 대기 |
| `55` | `0x0010F880` | `u32` | 줄 간격 |
| `65` | `0x0010F960` | `u32` | 문자 좌표 |
| `6A` / `6B` | `0x0010F6A0` | 타입 + NUL 종료 라벨 | 점프 |
| `6C` | `0x0010F6C0` | `u8 size`, 선택 헤더, 타입·NUL 종료 목적지들 | 선택지 |
| `6F` | `0x0010F780` | `u8 size`, wipe ID와 인자 | 화면 전환 |
| `70` | `0x0010FAE0` | `u8 size`, 변수·비교·값·목적지 | 조건 분기 |
| `72` / `73` / `74` | `0x0010F7E0` / `0x0010F820` / `0x0010F800` | `u8 size`, NUL 종료 ASCII 이름 | 장면 준비 / 실행 / 캡션 |
| `75` | `0x0010F920` | `03, r, g, b` | 본문 색상 |

`0x16`의 초기화 래퍼는 `0x0010F700`이며 `0x0010F70C`에서 생성자 `0x00127E28`을 호출한다. 이 명령은 별도 피연산자를 읽지 않고 표시·분기 상태를 바꾸는 EE 호출도 하지 않는다. 첫 두 선택 목적지에서는 첫 문장의 `0x04` 뒤에 나오므로 VM은 화면 효과를 만들지 않되, 선택 응답 화면을 다음 명령과 합치지 않도록 pause 경계로 내보낸다.

첫 이름 입력부터 첫 선택지까지 과거 수작업 표시값과 원본 명령의 대응은 다음과 같다.

| 기존 수작업 값 | 원본 명령 근거 | VM 처리 |
| --- | --- | --- |
| 여자친구 소개 전 20프레임 대기 | `my01_0055` 파일 오프셋 `0xB2A4D`의 `50 00 00 00 14` | `wait` 이벤트, 59.94Hz 기준 20틱 |
| 본문 이름 치환 | `0x0D` / `0x0E` | VM 이름 슬롯 0/1 삽입 |
| 줄바꿈과 페이지 대기 | `0x04` / `0x09`, 블록 말미 `0x0B` | 누적 텍스트 줄바꿈, pause 이벤트; `0x0B` 다음 실행 전에 버퍼 초기화 |
| `nativeGlyphWidth:true` | 이 구간에 `0x46` 없음 | 원본 글리프 폭, 추가 자간 0으로 렌더링 |
| `advanceMark` 좌표 | 이 구간에 `0x65` 없음 | 원본 명령으로 설명되지 않아 미확정; VM 구간에서는 기본 마커 좌표 사용 |
| 글자 속도 | 이 구간에 `0x40` 없음 | 기본 속도 1 사용 |

고정된 59.94Hz 비교 시계로 `8a97f1d` 기반 웹과 VM 웹을 같은 입력으로 진행해 첫 선택 화면과 `my01_0075`, `my01_0073`의 첫 화면을 캡처했다. 세 캔버스 모두 변경 픽셀 0개로 일치했다.

#### 음악 명령의 위치

첫 선택지까지의 `scenario.sn4` 명령열에는 Ogg 파일명이나 페이드 프레임을 직접 받는 음악 opcode가 없다. SN4의 `0x73`(SceneExec)과 `0x74`(CaptionExec)가 `my0002*` 같은 ScenePack 항목을 지정하고, 실제 파일명은 `SCENARIO/scene_pk.spk` 쪽 리소스 표에 있다. 예를 들어 `my0002e_00` 계열 표에는 `k1a001.ogg`와 `my0002.ipu`가 함께 기록된다. 따라서 현재 확인된 인터페이스는 아래와 같으며, SN4 VM이 존재하지 않는 음악 opcode나 페이드 값을 만들어 내지는 않는다.

| 계층 | 명령/인자 | 확인 결과 |
| --- | --- | --- |
| SN4 | `0x73 size "my0002e\\0"`, `0x74 size "my0002e_00\\0"` | ScenePack 장면과 캡션을 선택 |
| ScenePack 재생 | `14 00`, 문자열 토큰 `27 00`, 값 토큰 `2F/2E/2B`, 명령 ID `07 00` | Ogg 시작; `2F` 볼륨, `2B` 페이드 프레임, `2E` 완료 대기 플래그 |
| ScenePack 정지 | `15 00`, 값 토큰 `2B/2E`, 명령 ID `07 00` | Ogg 정지; `2B` 페이드 프레임, `2E` 완료 대기 플래그 |
| 웹 연결 | SN4 `0x74` 훅 → ScenePack 항목 | 배경과 음악을 같은 VM 이벤트에서 적용 |

`my0002b_00`, `my0002d_00`, `my0002e_00`의 100바이트 명령열은 동일하다. 음악 부분은 `14 00 27 00 "k1a001.ogg\0" 2F 00 32 00 2E 00 00 00 2B 00 00 00 07 00`이다. 즉 시작 opcode는 `0x14`, 실행 명령은 `0x07`, 파일은 `k1a001.ogg`, 볼륨은 50, 완료 대기와 페이드 프레임은 0이다. 전체 명령 영역에서 같은 시작 형식 689건과 정지 형식 389건을 대조했다. 정지는 `15 00 2B 00 <frames> 2E 00 <wait> 07 00`이며 `2B` 값은 0·30·60·90·120·180·240처럼 프레임 단위로 쓰인다.

첫 분기의 다음 캡션 `my0002e_10`은 `17 00 2F 00 14 00 2B 00 78 00 2E 00 00 00 0A 00`을 포함한다. `0x17`은 EE의 `BGM_CHANGE_VOL`이며 볼륨 20, 페이드 120프레임, 완료 대기 0이다. 웹은 현재 곡을 다시 시작하지 않고 같은 선형 gain을 120프레임 동안 내부값 25(`floor(20×127/100)`)로 바꾼다. ScenePack 명령의 `2E`가 0이 아니면 캡션 훅이 `fadeFrames + 1`틱을 반환하고 SN4 VM은 그 wait 이벤트가 끝날 때까지 다음 명령을 실행하지 않는다. 이 범위에서 실제로 지난 시작 4건과 볼륨 변경 1건의 `2E`는 모두 0이며, 첫 비영(非零) 대기 명령의 실장면 시간 대조는 다음 확장 범위에 남아 있다.

EE `bgm_play`(`0x001BD870`)는 `0x001BEDF0`에서 현재 파일명을 얻어 `0x001F5C14`로 요청 파일명과 비교한다. 비교 결과가 0이면 큐 삽입 전에 반환하므로 같은 파일의 `0x14`는 재시작도 볼륨 변경도 하지 않는 완전한 no-op이다. 웹도 이 경우 기존 재생 위치와 직전 `0x17` 볼륨을 그대로 유지한다. `bgm_stop`(`0x001BD960`)은 정지 큐 항목을 만들기 전 전역 현재 이름 값 `0x00225DC0`을 즉시 0으로 만든다. 따라서 페이드 중에 같은 파일의 `0x14`가 와도 새 재생으로 취급한다. 새 VM 범위에서 첫 실제 정지는 `my0002i_00`의 `scene_pk.spk` `0x72518`이며 페이드와 대기는 모두 0이다. 종전 분석에서 `my0006c_00` 범위를 잘못 잡아 `0x7280D`의 정지를 연결한 것은 오류다. 실제 `my0006c_00`(`0x7277D`)은 `k2h003.ogg`의 같은 파일 `0x14`이고, `0x7280D`의 180프레임 정지는 뒤의 `my0008_10`이다. 이 범위의 음악 명령에서 `2E != 0`은 아직 나오지 않았다. 효과 명령 `0x7B`의 첫 페이로드는 `my02_0030`의 `scenario.sn4` `0xB37A4`에 있는 `sh01_0010`이며, 바이트는 `7B 0C 13 73 68 30 31 5F 30 30 31 30 00 06`이다. EE 디스패치 `0x0010FD20`은 생성자 `0x00133AE8`을 사용하고, 실행 메서드 `0x00133AF8`은 payload를 `u8`, NUL 종료 문자열, `u8` 순서로 읽어 `0x001197D8`에 전달한다. 같은 라벨은 `my02_0035`, `0075`, `0080`, `0083`, `0085`, `0090`에서도 반복된다.

EE ScenePack 디스패처 `0x0013D140`은 시작의 `2F/2B/2E`를 차례로 `0x00144338`에 전달하고, 정지의 `2B/2E`를 `0x00144420`에 전달한다. 오디오 작업 스레드 `0x00142E50`은 이를 각각 `0x001BD870`과 `0x001BD960`으로 넘긴다. 두 함수 모두 `2B`를 16비트 페이드 길이로 저장하며 `2E`가 0이 아닐 때 `0x001BF110`으로 `2B + 1`회 갱신을 기다린다. 따라서 `2E`는 페이드 길이가 아니라 완료 대기 플래그다. 볼륨 함수 `0x001BE2E8`은 `(value * 127) / 100`을 정수 나눗셈으로 계산한다. 볼륨 50은 내부값 63이며 웹은 이를 `63/127` 선형 gain으로 재현한다.

EE 명령 초기화 루프는 `0x0010F5D8`에서 명령 번호에서 2를 빼고 `0x0021A240`부터 4바이트 단위로 분기표를 읽는다. `0x6C`의 항목 `0x0021A3E8`은 `0x0010F6C0`을 가리킨다. 여기서 호출하는 생성자 `0x00127618`은 객체의 +4에 ELF의 `CommandSelect` 가상 함수 테이블 주소 `0x00213578`을 쓴다. 첫 메서드 `0x00127858`은 `0x00127864`에서 공통 처리 루틴 `0x00127628`로 점프한다. 바로 앞의 `0x6A`와 `0x6B`는 모두 `CommandJump` 생성자를 호출한다. 원본 새 게임에서 실제로 표시되는 선택 문구와 활성 경로는 별도 화면 대조가 필요하다.

도입부의 콘솔과 눈 내리는 펜션 배경은 각각 `GRA/MY/my0007.ipu`와 `my0645.ipu`다. SN4의 라벨·문자열과 ScenePack의 리소스 목록을 원본 실행 화면과 대조했다. `SCENARIO/sn4.fnt`의 2,874개 글리프는 CP932 문자 코드와 폭·높이·상단 여백을 갖는다. 각 런의 상위 4비트는 픽셀 수, 하위 4비트는 색 인덱스다. 모든 글리프의 픽셀 수와 다음 인덱스 경계를 검증했다. 이름 키보드는 `namkan.txt`의 빈 줄을 경계로 11개 그룹을 구성한다.

오프닝 PSS의 MPEG-2 영상과 private stream 1의 `SShd/SSbd` 스테레오 PCM을 함께 변환한다. 음원은 48kHz, 16비트 리틀 엔디언이고 채널별로 512바이트씩 번갈아 저장된다. 첫 오디오 PTS와 첫 비디오 PTS의 차이를 유지한다.

타이틀과 선택지 위젯의 결정·커서 이동은 같은 효과음 경로를 사용한다. 결정 호출 `0x00108BB4`는 `a0=2`, 이동 호출 `0x00108C78`은 `a0=4`를 설정하고, 둘 다 `a1=60`, `a2=a3=a4=0`으로 공통 함수 `0x001BDA78`을 호출한다. 웹의 선택지는 각각 `assets/confirm.wav`, `assets/move.wav`를 재생하고 볼륨을 `0.6`으로 설정한다. 이름 확인창에서도 같은 ID를 사용한다. `se000.seb`에서 단일 보이스 시퀀스의 악기 번호를 읽고 WD 뱅크 1000의 해당 PS-ADPCM 샘플을 디코딩한다. 원본 실행에서 대기가 끝나는 위치를 대조해 대사 뒤의 책과 화살표도 디스크의 `EFFECT/mark.ctf`로 표시한다. ### 기억을 되짚는 경로의 장면 전환

초대장 서명자 소개 뒤 `my01_0082`의 `CommandIf`(0x70)는 시나리오 변수 `0x0124`를 1과 비교한다. EE `0x001013D8`은 `0x00225EB8 + 2 × 인덱스`에서 부호 있는 16비트 값을 읽는다. 비교표 `0x002196B0`의 연산자 12는 같지 않음, 7은 같음을 검사한다. 조건이 참이면 다음 명령을 실행하고 거짓이면 `0x0012EC20`에서 라벨 이동을 호출한다. 따라서 값이 1이 아니면 즉시 전화 경로 `my01_0085`로 점프한다. 1이면 여자친구에게도 초대장이 왔는지 묻고, 전화 경로와 불길한 예감 경로 `my01_0083` 사이의 선택 명령에 도달한다. 시나리오 파일에서 즉시값 대입 패턴 `68 05 01 24 06 00 vv`는 다섯 곳에 있다. `end02_0000`(파일 오프셋 `0x191F0C`), `top01_3020`(`0x196EC2`), `top01_3030`(`0x19718E`), `top01_3040`(`0x1975C8`)은 1을 쓰고, `top01_6000`(`0x197A62`)은 0을 쓴다. 새 게임에서 분기 직전까지 실제로 실행되는 경로와 세이브 복원 직후 값은 별도 검증 대상이다.

전화 인사 직전과 인사 중의 `0x50`(`CommandWait`)은 차례로 30, 20, 20을 읽는다. EE `0x0012D23C`에서 호출하는 `0x00112DE8`은 카운터에 값을 쓰고 입력 단축 플래그를 0으로 설정한다. 업데이트 호출 `0x00112740 → 0x00112E08`은 이 모드에서 버튼 검사를 건너뛰고 양수 카운터를 호출당 1씩 줄인다. `0x0012D244`에서 인수 13으로 호출한 함수가 참을 반환하면 `0x0012D258`에서 카운터를 즉시 0으로 다시 설정한다. 이 일본 한정판 실행 파일에서 피호출 함수는 `jr ra`와 지연 슬롯의 `move v0, zero` 두 명령뿐이므로 항상 0을 반환한다. 따라서 이 호출을 통한 대기 생략은 발생하지 않는다. 메인 루프(역분기 `0x00101148 → 0x00101068`)에서 `0x001010BC → 0x0010BA28`, `0x0010BA38 → 0x001126A0`을 거쳐 활성 시나리오를 한 번 갱신한다. 갱신 함수는 카운터를 줄인 직후 `0x00112748 → 0x00112EC0`에서 잔여값을 검사한다. 양수이면 이번 갱신의 후속 명령 처리를 건너뛰며, 0이면 다른 대기 사유가 없을 때 같은 갱신에서 후속 처리가 가능하다. 따라서 단위는 시나리오 갱신 횟수이며, 메인 루프 한 회의 실제 시간은 별도 대조가 필요하다. 루프 끝의 대기와 작업 스레드의 신호는 같은 객체(GP−0x6ED8)를 사용한다. 작업 스레드는 메시지 종류 0 처리부(`0x00153D00`)에서 신호 후보 플래그 s2를 세운다. 후보여도 GP−0x6EB0의 부호 있는 값이 2 미만이고, `0x00154EC8`이 참(GP−0x6E60 값이 2 이상)이고, 스택 +0x14의 비트 0이 켜져 있으면 `0x001541F8`에서 s2를 지운다. 이때 `0x0015420C`가 메시지 대기로 돌아가므로 신호 호출 `0x00154268`에는 도달하지 않는다. 따라서 수신 메시지 수만으로 시나리오 갱신 횟수를 계산할 수 없다.

날짜 화면 `my02_0010`의 `4C 05 30`은 글꼴 인수 두 개를 독립적으로 설정한다. EE `0x0012ADAC`와 `0x0012ADBC`에서 각 1바이트를 읽고 `0x0012ADCC → 0x0016E700`으로 전달한다. 첫 인수 5는 `0x0016C508`에서 텍스트 상태 +0x14에, 두 번째 인수 48은 `0x0016C550`에서 +0x10에 저장된다. 각 인수가 255이면 해당 필드를 유지한다. 두 번째 인수가 0이면 `0x001703E8`이 반환하는 기본값을 사용한다. 뒤따르는 `40 00`은 별도의 속도 명령이다. 이 저장 경로만으로 48과 화면 픽셀 높이의 비율은 확정할 수 없다.

재회 장면의 ScenePack 명령 `my0006_00`(`scene_pk.spk` 오프셋 `0x7269B`)에는 순서대로 `k2h003.ogg`, `my0006.m2v`, `my0006a.sab`가 있다. ISO의 `SANM/my0006[a-d].sab`에서 첫 32비트 리틀 엔디언 값은 파일 끝의 색인 위치다. 색인 +12의 개수는 a/b/c/d 순서로 13/26/13/13이며, +28부터 각 레코드의 파일 오프셋이 4바이트씩 이어진다. 네 파일 모두 각 레코드는 56바이트씩 연속하고 마지막 레코드 직후 색인이 시작된다. 색인 크기는 28 + 4 × 개수다. 이 개수만으로 재생 프레임 수나 표시 시간을 결정할 수 없다. 각 레코드의 +24/+28, +32/+36, +40/+44를 32비트 리틀 엔디언 쌍으로 읽으면 각각 (256,0)/(384,448)/(384,448) 또는 (320,0)/(320,448)/(320,448)이다. 따라서 두 사각형 후보 모두 640×448 화면의 오른쪽 끝과 일치한다. 같은 파일 안의 인접 레코드에서 +4 데이터 오프셋의 차이는 앞 레코드의 폭 × 높이 / 64와 일치한다(폭 384이면 2688바이트, 320이면 2240바이트). SAB a의 첫 레코드에서 +4 영역을 48열 × 56행의 바이트 배열로 보면 0인 배경과 연속된 비영역의 경계가 나타난다. +8 영역을 행 우선 2비트/픽셀로 가정하고 8×8 블록별로 비교하면, +4 값이 0인데 대응 블록에 비트가 있는 경우는 a와 c 전체에서 각각 0건이다. 같은 검사에서 b는 10,338건, d는 2,072건이어서 네 파일에 단순 행 우선 디코딩을 일괄 적용할 근거는 부족하다. b의 레코드 10·11은 +8 값 0x44460을 공유하지만 폭이 384에서 320으로 바뀌고, d의 10·11은 0x336E0을 공유하며 반대로 바뀐다. 실제 픽셀 배치와 공유 영역 해석은 추가 검증 대상이다.

재회 독백 다음 `my02_0040`(SN4 파일 오프셋 `0xB3963`)에는 선택 명령 없이 다섯 입력 대기가 나오며, 주인공이 여행 중 정식 연인이 되겠다고 다짐하는 문장에 여자친구 이름(`0x0E`)이 들어간다. 마지막 외침 전후에 `0x74`로 `my0006_20`, `my0006_30`을 실행한다. EE 명령 생성자와 ELF 가상 함수 테이블 이름으로 확인한 결과, `0x74 → 0x001299F8`은 CommandCaptionExec, `0x1E → 0x0012A0C8`은 CommandCaptionSync다. 느낌표 주변 `46 03`은 CommandMojiSpace(생성자 `0x0012BA10`), 말미의 `65 00 00 00 07`은 CommandMojiXY(`0x0012BD28`)다. 다음 블록 `my02_0075`에서 여자친구가 말을 걸 때는 `0x0D`가 주인공 이름 자리에 온다.

글자 속도 명령 `0x40`은 `0x00129308 → 0x001108E8`에서 피연산자를 엔진 +0x2A4에 쓰고 +0x29C 카운터를 0으로 재설정한다. 갱신 경로 `0x00112610–0x00112640`에서 속도가 0이면 +0x2A0 플래그를 즉시 1로 설정한다. 양수이면 카운터를 1 올린 뒤 지정값 이상일 때만 카운터를 0으로 되돌리고 같은 플래그를 설정한다. 따라서 속도 1과 2에서 이 경로가 플래그를 설정하는 간격은 각각 갱신 1회와 2회다. 문자 처리 루틴은 `0x00111C48`에서 이 플래그를 읽는다. 0이고 처리할 코드가 전각 공백(Shift-JIS `0x8140`)이 아니면 `0x00111C64`에서 읽기 위치 조정 함수에 −2를 전달하고 1을 반환한다. 전각 공백은 플래그가 0이어도 이 검사 지점을 통과한다. 일반 출력 경로에서 `0x00111FD8` 호출 뒤 `0x00112010`은 속도가 0이 아닐 때만 +0x2A0을 지운다(분기 지연 슬롯의 저장). 따라서 속도 0은 일반 경로에서 다음 문자에도 플래그가 유지된다는 점에서 속도 1과 다르다. 실제 프레임별 출력 수는 다른 종료 조건과 함께 대조해야 한다.

게임을 해 보지 않았다는 독백 뒤에는 `my02_0085`(0xB3CBC)와 `my02_0090`(0xB3D99)이 차례로 `my0006b_00`, `my0006c_00` 연출을 호출한다. 이어지는 `my02_0100`(0xB3E68)의 두 입력 대기 뒤 `6C 1C 01 02` 선택 명령이 두 목적지를 기록 순서대로 가리킨다. 첫 목적지 `my02_0110`(0xB3ED0)의 선택 문구는 다음에 빌려 달라는 대답이다. 둘째 `myb02_0010`(0x100790)은 자신도 게임을 해 보았고 재미있었다는 대답이다. 둘째 라벨의 헤더는 `85 0C 0D`로 시작하므로 본편의 `85 0B 0C`만 검색하면 놓친다. 실제 플레이 상태별 선택 가능 여부는 별도 대조가 필요하다.

초대장 첫 페이지 `my01_0078`에서 `0x04`는 줄바꿈이고 `0x09`는 입력 대기다. EE 명령 초기화 표에서 각각 `0x0010F640 → 0x00124348`의 `CommandBr`, `0x0010F660 → 0x001249A8`의 `CommandPause`로 연결된다. 앞 두 줄 사이에는 줄바꿈만 있으며 인사말 끝에 줄바꿈과 대기가 함께 나온다. 다음 네 줄 사이에도 줄바꿈만 있다. 서식 명령 `0x4C`, `0x55`, `0x5D/0x61`은 각각 `CommandFont`, `CommandLineSpace`, `CommandMargin` 생성자로 연결된다.

`my01_0073`의 점프 목적지 `mo01_0000`은 곧바로 `mo01_0011`로 이어진다. 다음 위치는 모두 추출한 `SCENARIO/scenario.sn4`의 파일 오프셋이다.

## 재현과 검증 범위

Ghidra 12.2와 Emotion Engine 확장의 `r5900:LE:32:default` 언어로 함수 10개를 디컴파일하고 직접 호출 14곳을 확인했다. 아래에서 `$headless`는 설치된 Ghidra의 `support/analyzeHeadless.bat` 경로다. 실행 파일과 Ghidra 데이터베이스는 로컬 출력 경로에 보관한다.

```powershell
python -B ports/kamaitachi2-ps2/disc.py "$iso" --elf outputs/kamaitachi2-ps2-kor/ghidra/SLPS_251.32
& $headless outputs/kamaitachi2-ps2-kor/ghidra Kamaitachi2-Opening -import outputs/kamaitachi2-ps2-kor/ghidra/SLPS_251.32 -processor r5900:LE:32:default -scriptPath ports/kamaitachi2-ps2/ghidra -postScript OpeningChecks.java
```

원본 ISO를 로컬 Play! 브라우저 런타임에서 별도로 실행해 새 게임, 자동 저장을 쓰거나 건너뛰는 경로, 두 입력창의 기본 이름, 취소와 확정, 변경된 이름이 다음 문장에 들어가는 지점을 대조했다. PCSX2에서는 메모리 카드 미삽입 시의 안내도 관찰했다. 이 웹 빌드는 사용 가능한 가상 카드로 시작한다. [Play! 공식 브라우저 런타임](https://playjs.purei.org/)

웹 회귀 검사는 준비한 빌드와 Playwright의 새 Chromium 세션을 사용한다. 테스트는 준비된 사이트의 HTML·JS·CSS·JSON·미디어만 허용하고 ISO 요청 건수와 파일 선택창 유무도 확인한다. 공통 테스트 환경과 같은 위치인 `web-player/node_modules`나 그 상위에 Playwright를 설치한다. 두 번째 인자로 디렉터리를 넘기면 검사 화면을 로컬에 기록한다.

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = '0'
node ports/kamaitachi2-ps2/test-browser.mjs http://127.0.0.1:8772/ outputs/kamaitachi2-ps2-kor/browser-check
```

두 이름의 입력 순서, 한 글자 추가·삭제, 초기 이름 복원, 여섯 번째 자리 교체, 확인창의 기본 선택과 되돌아가기, 다음 대사에 반영되는 값까지 검사한다. 웹 자동 저장은 해당 브라우저의 로컬 체크포인트를 사용한다. 타이틀 환경설정과 기존 PS2 메모리 카드 가져오기는 현재 범위 밖이다. 강설, 화면 전환, 글자 출력 속도, 버튼 효과음의 프레임·샘플 단위 일치는 검증이 남아 있다.

### 선장에게 묻는 질문

`SCENARIO/scenario.sn4`의 `my02_0330`(0xB4E0A)은 주인공이 선장에게 질문한다는 문장 뒤에 두 개의 조건부 선택 명령을 둔다. 첫 조건의 피연산자는 `01 1D 07 00 01`, 다음 조건은 `01 1D 0C 00 01`이다. 위 EE 비교표와 대조하면 둘 다 변수 0x011D를 1과 비교한다. 값이 1이면 세 항목, 그 외에는 두 항목이다.

| 순서 | 질문 | 목적지와 첫 응답 |
| --- | --- | --- |
| 1 | 늘 손님을 실어 나르는지 | `my02_0340` (0xB4EE2). 오늘은 아비코라는 남자가 배를 전세 냈다고 답한다. |
| 2 | 왜 미카즈키섬이라고 부르는지 | `myb02_0320` (0x1017BB). 섬이 초승달 모양이라고 답한다. |
| 3 (변수가 1일 때) | 아비코는 어떤 사람인지 | `my02_0335` (0xB4E9A). 선택 문구 직후 `6A` 명령이 `ak01_0000` (0x3C6A)으로 이동한다. 그 라벨의 장 제목은 「１章：網曳の名」다. |

즉시값 대입 패턴 `68 05 01 1D 06`을 검색하면 `end01_0000` (0x1916E4), `top01_3010` (0x196C2B), `top01_3020` (0x196D96), `top01_3030` (0x19707F), `top01_3040` (0x1974AE)에서 1을 쓴다. `top01_6000` (0x1979C1)은 0을 쓴다. 특정 세이브에서 이 대입이 실행됐는지는 분기 직전의 변수값을 별도로 관찰해야 한다.

### 동요 첫 화면의 세로쓰기

`my03_0040` (SN4 라벨 0xB5FF9)에서 다음 라벨 `my03_0050`까지 명령 본문은 1,589바이트다. `my0023_00` 호출 뒤 90틱을 기다리고 `my0023a_00`을 호출한다. 글자 배치는 131개이며 각 배치의 `0x66` 뒤에 부호 있는 16비트 빅엔디언 x·y가 온다. 그중 33개는 후리가나를 전각 공백에 붙인다. 첫 본문 글자 底는 (538, 32), 독음 そ와 こ의 공백 기준점은 각각 (557, 47), (559, 62)다. 추출기는 공백과 독음을 따로 보존한다. 모든 배치가 끝나면 속도를 1로 복원하고 160틱 대기한다. 뒤이어 (60, 210) 좌표와 페이지 끝 명령이 나온다. 이 위치는 가사 글자 수에 포함되지 않는다.

### 저작권 화면의 종료 조건

EE `0x00107C8C`는 네 번째 인자 140을 s1에 보존한다. `0x00107D18`에서 상태 조회 함수 `0x0019B108`을 호출하고 반환값이 3일 때만 카운터를 검사한다. `0x00107D30`은 감소 **전** 값이 0 이하이면 종료 경로로 분기하고, 양수이면 `0x00107D38`에서 1을 뺀다. 입력 없이 진행하면 상태 3을 140번 관찰해 0이 되고 141번째 관찰에서 종료를 요청한다. 이어서 `0x00107D68` 루프가 상태 5까지 기다린다. 상태 조회 횟수와 실제 화면 표시 프레임 수의 관계는 아직 측정이 필요하다.

웹 구현은 59.94Hz 기준 140틱을 사용한다. 로컬 Chromium에서 로고 자연 종료 후 canvas의 `data-scene` 변경 시각을 MutationObserver로 기록했을 때 `copyright` 진입부터 `opening` 진입까지 한 실행에서 2340.8ms였다. 이 값은 웹 장면의 경과 시간이며 원본의 실측 재생 시간은 별도로 대조해야 한다.

각 조회 뒤에는 공통 갱신 함수 호출이 한 번 있다(`0x00107D20 → 0x00154480`). 이 함수는 `0x001544C8`에서 gp−0x6ED8에 저장된 핸들을 인자로 `0x001CCD60`을 호출한다. 해당 래퍼는 v1=0x44로 syscall을 실행한다. 같은 핸들은 초기화 중 `0x00153A38`에서 인자 (1, 0)으로 호출한 함수의 반환값이며, `0x00154268`에서 다른 래퍼 `0x001CCD40`에도 전달된다. 따라서 다음 상태 조회까지의 간격을 계산하려면 이 핸들을 사용하는 생산자 쪽 실행 빈도도 확인해야 한다. 상태 조회 자체는 `0x0019B144`에서 활성 객체 +0x4B4에 반환 상태를 기록하며, 활성 객체가 없으면 `0x0019B150`에서 상태 5를 반환한다.

`SYSTEM/opening.pss`의 첫 디코딩 프레임 시각은 90kHz 기준 11373(0.126367초)이고 마지막은 10945296이다. 인접한 3642개 프레임의 시각 차이는 모두 3003이다. FFprobe가 스트림에 보고하는 시작 시각 0.193100초는 첫 디코딩 프레임 시각과 다르다. 웹 변환기는 첫 프레임을 영상 시각 0으로 옮기고 PCM의 첫 PTS도 같은 기준으로 맞춘다. FFprobe의 `-count_frames`로 원본 PSS와 출력 MP4를 각각 디코딩하면 로고 153, 오프닝 3642, 타이틀 대기 영상 pre_dv 5835프레임이다.

오프닝 첫 오디오 PTS도 11373/90000초이고 PCM은 48kHz 스테레오다. 웹 MP4의 영상·음성 스트림 시작 시각은 둘 다 0이다. 파일 안의 동기를 확인하기 위해 FFmpeg로 AAC를 16비트 스테레오 PCM으로 디코딩한 뒤 원본 PCM의 10·60·110초 지점부터 각 채널의 4096샘플을 비교했다. 예상 위치 ±2048샘플에서 내적을 두 구간의 L2 노름 곱으로 나눈 값이 최대인 위치를 선택했다. 6개 구간 모두 지연은 0샘플이었다. 최대 상관값은 시각 순서대로 좌/우 0.99959/0.99945, 0.99879/0.99811, 0.99550/0.99420이다. 이 측정은 변환된 파일의 파형 정렬에 해당하며 브라우저와 원본 기기의 출력 지연은 포함하지 않는다.

같은 파형 검사를 로고와 타이틀 대기 영상에도 적용했다. 각 PCM 길이의 15%, 50%, 85%에 해당하는 샘플(소수점 버림)에서 시작했다. 디코딩한 원본과 MP4의 채널당 샘플 수는 로고에서 각각 244992개, 대기 영상에서 각각 9345536개로 같았다. 둘 다 48kHz이며 첫 오디오와 첫 영상의 시각 차이는 0샘플이었다. 측정한 12개 구간 모두 최대 상관 위치가 예상 위치와 일치했다. 좌우 채널과 세 시각을 통틀어 최소 상관값은 로고 0.99575, 대기 영상 0.99878이었다.

### 타이틀과 이름 입력 장면의 음악 반복

로컬 웹 빌드의 Ogg 파일에 대해 `ffprobe -v error -show_entries stream=sample_rate,duration_ts:stream_tags -of json 파일명`으로 Vorbis 주석을 확인했다. 타이틀 곡 k2t002는 48000Hz·5514644샘플에 L=475399, 이름 입력 전부터 재생되는 k1a001은 48000Hz·5626372샘플에 L=1017889다. 나머지 k1a004, k2h002, k2h003, k2h017에도 서로 다른 L 값이 있다. EE 실행 파일 오프셋 0x126A08(적재 주소 0x00225A08)에 널 종료 문자열 `L=`이 있고 인접 데이터에 `vorbis`, `OggS`가 있다. 웹 플레이어는 현재 HTML 오디오의 전체 파일 반복을 사용한다. L이 절대 샘플 단위의 반복 시작점이라는 가설이면 타이틀과 k1a001의 복귀 시각은 각각 9.904초, 21.206초다. 적용하려면 원본에서 이 값을 읽어 위치를 변경하는 경로를 확인해야 한다.

EE에서 L 값을 실제로 읽는 경로를 확인했다. `0x001C30EC–0x001C311C`는 객체 +0x20의 개수와 +0x28의 문자열 포인터 배열을 사용해 각 항목의 처음 두 바이트를 주소 0x00225A08의 문자열과 비교한다. 일치하면 `0x001C3130`에서 해당 문자열 +2를 숫자 변환 함수에 넘긴다. 변환 래퍼 `0x001F3A94`의 세 번째 인자는 10이며 반환값을 32비트 부호 확장한다. `0x001C3138`은 결과를 객체 +0x30에 64비트로 저장하고 검색을 종료한다. 이 경로는 첫 번째 일치 항목의 십진 정수 해석을 확인한다. 샘플 위치 단위와 재생 종료 시의 적용 여부를 확인하려면 저장된 필드를 읽는 경로를 추적해야 한다.

L 값을 보관하는 객체의 소유 경로도 확인했다. `0x001C9D08`의 첫 인자가 상위 객체이고 두 번째 인자가 배열 인덱스다. `0x001C9D34`가 인덱스를 4배 하고 `0x001C9D88–0x001C9D94`가 상위 객체 +0x2C의 포인터 배열에서 항목을 읽는다. 래퍼 `0x001CBF58`은 항목의 첫 워드를 다시 역참조해 `0x001C2FD8`로 전달한다. 따라서 +0x30은 이 두 번째 역참조로 얻은 객체를 기준으로 한 오프셋이다. 앞선 유형 1 처리도 같은 배열 항목을 사용하며 유형 3 처리 뒤에는 유형 5 헤더를 요청한다. 같은 오프셋을 쓰는 다른 디코더 구조와 구분하려면 이 포인터 경로까지 일치하는지 확인해야 한다.

파형만으로 반복 위치를 판단할 수 있는지도 검사했다. FFmpeg로 디코딩한 각 Ogg의 왼쪽 채널에서 끝 8192샘플과 L 직전 8192샘플의 정규화 내적(평균 제거 없음)을 구했다. k2h003은 0.994, k2h002는 0.930으로 유사했다. 같은 방법으로 타이틀 k2t002는 0.021, 이름 입력 k1a001은 0.064였다. L 주변 ±1024샘플을 검색해도 두 곡의 최댓값은 각각 0.257, 0.675였다. 반복 구간이 음악적으로 이어져도 경계 앞 파형이 같을 필요는 없으므로, 이 비교만으로 두 곡의 반복 주소를 확정하거나 배제할 수 없다.

타이틀 메뉴의 최대 인덱스는 고정 상수가 아니다. EE `0x00108AE4–0x00108AEC`에서 s3=3, s2=2를 준비하고, `0x00108AFC → 0x00108AB0 → 0x00107848`의 반환값을 검사한다. `0x00108B08`에서 a1=3을 설정한 뒤 `0x00108B18`의 movz가 반환값 0일 때 a1을 2로 바꾼다. `0x00108C40–0x00108C5C`는 현재 인덱스가 이 상한보다 작고 오른쪽 입력이 있을 때만 인덱스를 증가시킨다. 따라서 조건에 따라 0~2 또는 0~3을 탐색한다. 결정 시 `0x00108BB4`의 효과음 호출은 인덱스 분기보다 먼저 일어나고, 인덱스 0/1/2/3은 다음 선택값 1/2/4/3에 대응한다. 웹 구현은 현재 세 항목을 표시한다. 네 번째 항목의 표시 조건과 문구는 별도의 검증이 필요하다.

타이틀 텍스처 `title_00`에서 네 번째 문구는 「ラブテスター」(러브 테스터)다. 비선택 상태는 (128,32), 선택 상태는 (128,96)에서 시작하는 128×32 영역이다. 표시 판정 `0x00107848`은 gp−0x7A00 값이 0이면 즉시 0을 반환한다. 이 값이 0이 아니면 함수 `0x0017A070(7)`이 0이 아닐 때 1을, 0일 때 gp−0x7A04 값을 반환한다. 첫 필드는 `0x00102A00`의 호출 결과이며 이 호출의 세 번째 인자는 주소 0x00219868의 `edit0:SCENARIO/love.sn4` 문자열이다. Special Box ISO FAD에도 `SCENARIO/love.sn4`(247376바이트)가 있다. 파일 존재만으로 새 게임에서 해당 항목이 열린다고 판정할 수는 없다.

이 판본의 `0x0017A070`은 인자와 관계없이 0을 반환하는 두 명령뿐이다. 따라서 기본 실행 파일에서 러브 테스터의 표시 조건은 gp−0x7A00과 gp−0x7A04가 모두 0이 아닌 경우로 좁혀진다. 후자의 설정 경로 중 하나는 시나리오 변수 0x0004를 검사한다. `0x001019A8`은 0x002196F0의 18개 변수 번호를 순회해 함수 0x001013D8이 비영 값을 반환한 항목의 비트를 세운다. 표의 첫 두 번호는 3과 4다. `0x001066FC`가 비트 1을 추출하고 결과를 레코드 +0x88에 저장한다. 그 값이 0이 아니면 `0x0010674C`에서 gp−0x7A04에 1을 쓴다. 다른 경로는 `0x001041C8`에서 항목 시작점(+0x5C0) 기준 +0x88을 읽고 해당 값이 있는 항목을 찾으면 `0x00104270`에서 같은 플래그를 세운다. 변수 4가 어느 이야기 진행 시점에 설정되는지는 시나리오 명령 대조가 필요하다.

Special Box의 `SCENARIO/scenario.sn4`에서 변수 4 대입 접두부 `68 05 00 04`를 검색하면 5곳이다. `end02_0000`의 0x191EC2, `top01_3020`의 0x196E77, `top01_3030`의 0x19715B, `top01_3040`의 0x197593에서는 뒤에 `06 00 01`이 붙어 1을 쓴다. `top01_6000`의 0x19794E에서는 `06 00 00`으로 0을 쓴다. 라벨은 점프 대상 문자열과 구분해 0x85 정의 명령을 대조했다. 앞의 두 설정 지점 바로 뒤에서는 같은 리소스 end0010과 end0010_00을 지정한다. `SCENARIO/love.sn4`에는 이 접두부가 없다. 따라서 본편에서 end02_0000의 해당 명령에 도달하면 활성화에 사용되는 변수가 설정된다. 이후 저장 기록에 반영되는 시점과 플레이어에게 표시되는 엔딩명은 별도 확인 대상이다.

타이틀 진입 전 `0x00102BD0`는 간격 32바이트인 두 항목을 검사한다. 상태(+0)가 1이고 값(+12)이 양수인 항목이 있으면 1을 반환한다. 이 결과는 `0x00100248`의 두 번째 인자로 전달되어 gp−0x78F0에 저장된다. `0x001088AC → 0x00108A60`은 값이 비영이면 기본 인덱스 1, 0이면 인덱스 0을 gp−0x78C0에 쓴다. 웹판은 유효한 브라우저 체크포인트가 있을 때 「続きから」를 기본 선택한다.

이름 확인창은 EE 0x0011D658에서 ○를, ○가 없으면 0x0011D6A0에서 ×를 검사한다. 두 입력이 없을 때 0x0011D6F4의 마스크 0x8050(□·위·아래) 중 하나라도 눌리면 선택값을 한 번 뒤집고 이동음을 낸다. 웹판에서는 A 키가 □에 대응한다.

타이틀의 버튼 입력은 현재 눌린 상태에서 새로 눌린 비트만 추출한 값이다. `0x00108824–0x0010882C`가 gp−0x78F8을 출력 주소로 넘긴다. 입력 갱신 시 `0x0015A7D8–0x0015A7F0`은 이전 상태를 반전해 현재 상태와 AND한 결과를 보관하고, `0x0015A7FC`가 이를 출력한다. `0x001088CC–0x001088D8`이 이 값을 메뉴 처리기로 전달한다. 확인 마스크가 비어 있을 때에만 `0x00108BA0`에서 좌우 분기 0x00108C18로 이동한다. 따라서 이미 누른 오른쪽을 계속 유지하는 것으로는 다른 항목으로 다시 이동하지 않으며, 새로 누른 확인과 방향이 겹치면 현재 선택을 결정한다.

### 이름 입력 직전 본문 위치 검증

640픽셀 폭에서 펜션 소개와 주인공 소개를 비교했다. 캡처 전체를 회색조로 변환하고 y=50, 90, 130에서 시작하는 27픽셀 높이 띠마다 밝기 165를 넘는 픽셀이 두 개 이상인 열을 골랐다. PS2와 브라우저 모두 본문은 x=35에서 시작했다. 펜션 소개 첫째·둘째·셋째 줄의 마지막 열은 PS2가 각각 593·328·580, 웹판이 591·326·578이었다. 주인공 소개 첫 줄은 각각 428과 426이었다. 각 값은 글자의 보이는 가장자리이며 폰트의 전진 폭을 직접 측정한 값은 아니다. 이름을 묻는 줄 끝에는 책 모양 진행 표시가 붙어 있어 이 비교에서 제외했다. 본문과 진행 표시를 배치할 때 640×480 캡처에서 측정한 y 좌표는 위 여백 16픽셀을 빼서 640×448 캔버스 좌표로 변환한다.
펜션 첫 소개 문장과 주인공 소개 첫 문장의 50글자를 개별 비교했다. 웹 캡처의 글자별 전진 폭을 기준으로 y=50 또는 90부터 27행을 잘라 PS2 캡처에서 x ±4, y ±3픽셀 범위를 정규화 상관으로 대조했다. 원본의 최적 가로 위치와 웹 위치의 차이는 0~2픽셀이었다. 관측 위치에 대한 가로 절대 오차의 합은 현행 비율 0.96에서 45픽셀, 같은 비율로 글자마다 전진 폭을 반올림하면 17픽셀, 누적 폭에 비율 0.963을 적용하면 15픽셀이었다. 두 대안 모두 최대 오차는 1픽셀이라서 이 캡처만으로 PS2의 계산식을 결정할 수 없다.

폰트 로딩 경로를 EE 실행 파일에서 추적했다. 0x001004A8–0x001004AC에서 선택하는 표의 첫 레코드(0x00219458)는 [4, 0x00219558, 8, 0]이며 두 번째 워드가 edit0:SCENARIO/sn4.fnt 문자열을 가리킨다. 0x001573E8은 0x001CCB40으로 분기해 시스템 호출 0x22를 실행한다. 표를 순회하는 코드는 0x001FE400의 첫 워드가 가리키는 0x00100518에 있다. 레코드 +4가 비영이면 0x0010057C가 스택의 출력 주소, 경로 포인터, 레코드 +8 값을 인자로 0x00165600을 호출한다. 0x00100584–0x0010059C는 결과 8바이트를 0x00225E80 + ID × 8에 복사한다. 따라서 폰트(ID 4)의 결과는 0x00225EA0에 저장된다. 레코드 간격은 16바이트이며 ID −1에서 종료한다. 결과의 내부 구조와 글자 폭 계산은 별도 추적 대상이다.

폰트 슬롯으로 복사되는 8바이트는 호출자가 제공한 출력 버퍼에서 온다. 0x00165600은 0x00165850에 임시 상태 주소, 출력 주소, 경로, 표의 세 번째 워드(폰트는 8)를 전달한다. 0x00165888의 호출은 별도 명령 번호 9를 사용한다. 이후 요청 구조의 +0x14에 출력 주소, +0x24에 표의 값 8을 쓰고 0x00165198에 구조를 넘긴다. 함수 반환 레지스터 v0는 0x001658A4에서 임시 상태 +0x10으로부터 채워진다. 리소스 표 순회 루프가 슬롯에 복사하는 값은 이 레지스터가 아니라 출력 버퍼의 첫 8바이트다. 두 워드 각각의 의미는 요청 처리측의 쓰기 명령을 확인해야 한다.

첫 워드의 의미를 소비측에서 확인했다. 0x00170160은 ID 4와 스택 출력 주소로 0x001006E0을 호출한다. 성공 경로는 슬롯 8바이트를 복사한 뒤 슬롯을 [0, −1]로 초기화한다. 0x00170174–0x00170180은 복사본 첫 워드를 gp−0x6A00에 보관하고 0x001701B8의 첫 인자로 넘긴다. 이 값은 메모리에 적재한 폰트의 시작 주소다. 첫 그룹은 시작 주소 +0x1C이고 그룹 +0x0C에서 글리프 수, +0x14에서 12바이트 항목 배열이 시작된다. 0x001701E0–0x001701F8은 각 항목 +8의 비트맵 파일 오프셋에 폰트 시작 주소를 더해 같은 자리에 포인터를 쓴다. 첫 그룹에서 얻는 파일 기준 글리프 수 위치 40과 항목 시작 위치 48은 웹 추출기의 sn4.fnt 파싱과 일치한다.

글리프 검색 함수 0x001702B0은 그룹 첫 두 워드를 a1·a2와 대조하고, 일치한 그룹의 12바이트 레코드 배열에서 첫 워드의 문자 코드(a0)를 이진 검색한다. 성공하면 해당 레코드 주소를 반환한다. 0x0016FD98의 호출 직후 0x0016FDA0이 레코드 +4를 부호 없는 바이트로 읽어 그대로 반환한다. 0x0016F13C의 호출부는 0x0016F148에서 같은 폭을 읽고 0x0016F150에서 정수 누산기에 더한다. 0x00170444에서도 폭에 1을 더하지만 다음 명령에서 2로 나누며, 이 경로는 비트맵 버퍼 처리에 사용된다. 이 명령만으로 본문 글자 사이에 1픽셀 간격이 있다고 판단할 수 없다. 본문 최종 좌표에 적용되는 추가 간격과 배율은 호출 경로를 더 확인해야 한다.

문자열 너비 계산에서 글리프 폭과 별도로 더하는 정수 필드를 확인했다. 0x0016FE10이 문자 코드로 폭 조회 함수 0x0016FD30을 호출하고, 0x0016FE20은 그 반환값을 누적한다. 0x0016FE1C의 호출은 0x0016E6B0 → 0x0016C580을 거쳐 렌더러 +4가 가리키는 객체의 +0x18 워드를 읽는다. 0x0016FE2C는 반복 분기의 지연 슬롯이므로 마지막 문자에도 이 값을 더한다. 0x0016C578은 같은 필드에 두 번째 인자를 쓰는 설정 함수다. 다른 계산 경로에서도 0x00136E98이 이 값을 미리 읽어 s6에 저장하고, 0x00136EF0–0x00136EF8은 글리프 폭과 s6을 더해 누적한다. 실제 펜션 장면에 설정되는 값과 화면 좌표 변환은 아직 확인하지 않았다.

자간 필드는 초기화 경로 0x0016C438 및 0x0016E2E4에서 0을 받는다. 실행 중에는 0x00113200에서 객체 +0x1C 값, 0x00117C90에서 객체 +0x188 값을 같은 설정 래퍼 0x0016E690에 전달한다. 또 0x0012A41C는 인자 4로 0x0010CC10을 호출해 반환값을 0x0012A428의 자간 설정에 넘긴다. 읽기 함수는 객체 +0xC8의 커서에서 한 바이트씩 읽고 누적값을 왼쪽으로 8비트 이동해 OR하므로 이 경로는 스트림의 4바이트 빅엔디언 값을 사용한다. 초기값만으로 개별 장면의 자간을 결정할 수 없다.

펜션·주인공 소개 50글자의 관측 위치에 대해 추가 간격 없이 원본 정수 폭을 누적하면 절대 오차 합이 45에서 17픽셀로 감소했다. 이 네 화면에 적용하고 브라우저에서 다시 캡처했다. 앞서 측정한 네 줄의 끝은 592·327·579·427로 각각 PS2보다 1픽셀 왼쪽이다. 이는 캡처 기반 보정이며 실제 장면의 자간 필드값은 미확인이다.

같은 50글자에서 전진 폭을 고정한 뒤 글자 이미지 크기를 독립 비교했다. 각 글자를 PS2 캡처의 x ±1, y ±2픽셀 안에서 정규화 상관으로 대조하면 가로·세로 0.96배의 평균은 0.921, 가로 1배·세로 0.96배는 0.975, 양축 1배는 0.955였다. 네 화면에 가로 1배를 적용해 브라우저에서 재캡처했다. 같은 밝기 기준에서 펜션 소개 세 줄과 주인공 소개 첫 줄의 우측 열은 593·328·580·428로 원본 측정값과 일치했다.

여자친구 이름 확정 직후의 원본 캡처와 같은 이름 真あ를 브라우저 저장 기록에 넣고 타이틀에서 이어하기로 검증했다. 첫 문장 彼女の名前は、真あ。에도 원본 글리프 폭을 적용하고 이어 쓰는 두 페이지에 같은 폭을 유지했다. 640픽셀 폭에서 y=50~76의 밝기 165 초과 픽셀이 두 개 이상인 열은 원본과 웹 모두 x=36~281이었다.

자동 저장 안내와 슬롯 선택 화면에서 카드 상태 문구의 최대 RGB 채널값을 비교했다. 원본의 비선택 슬롯은 108, 선택 슬롯은 218이며 카드 제목 배경도 비선택 시 대략 절반 밝기다. 웹판에서 제목과 문구에 밝기 조절을 적용한 후 캔버스에서 두 슬롯의 상태 문구를 측정했다. 안내 화면은 [108,108], 왼쪽 선택은 [219,108], 오른쪽 선택은 [108,219]였다.

도입 영상 3종의 초반 음성도 비교했다. 원본 PSS의 첫 PCM PTS와 첫 디코딩 영상 프레임 PTS 차이는 chunlogo, opening, pre_dv 모두 48kHz 기준 0샘플이었다. 웹 MP4의 AAC를 PCM으로 디코딩하고, 원본에서 4096샘플 간격으로 조사해 채널 표준편차가 100을 넘는 첫 검사 구간을 선택했다(검사 시작 샘플 4096). chunlogo·opening은 샘플 4096, pre_dv는 430080에서 시작하는 각 채널 4096샘플을 예상 위치 ±2048샘플에서 정규화 내적으로 대조했다. 좌우 모두 지연은 0샘플이었고 상관값은 각각 0.99882/0.99885, 0.99989/0.99990, 0.99984/0.99955였다. 이 검사는 파일 안의 동기를 측정한다.

도입·타이틀 영상 5개의 원본과 웹 MP4를 FFmpeg로 각각 디코딩해 모든 프레임을 순번대로 비교했다. title-1은 SYSTEM/title.mmv 첫 레코드의 섹터와 길이로 추출했다. 비교 필터는 scale=64:44:flags=area,format=gray이며 fps_mode=passthrough로 시간축 보간을 피했다. 8비트 회색조에서 프레임별 평균 절대 오차를 구한 결과(프레임 수, 전체 평균, 가장 큰 프레임 평균)는 chunlogo (153, 0.166, 0.486), opening (3642, 0.226, 0.672), pre_dv (5835, 0.291, 0.794), title-1 (121, 0.263, 0.433), title (241, 0.298, 0.433)이었다. 각 원본과 출력의 프레임 수는 같았다. 이 비교는 축소된 밝기 영상의 프레임 대응을 검증하며 원해상도 색상이나 브라우저 표시 시각을 측정하지 않는다.

원해상도 색상도 검증했다. 위와 같은 원본 5종과 웹 MP4를 FFmpeg로 디코딩하고 두 영상에 settb=1/30000,setpts=N*1001을 적용해 프레임 순번을 맞춘 뒤 psnr=shortest=1로 비교했다. PSNR(Y/U/V, dB)은 chunlogo 42.77/44.29/45.21, opening 42.65/43.96/45.09, pre_dv 43.61/45.76/46.14, title-1 43.71/46.06/45.91, title 42.22/43.57/43.38이었다. 프레임별 종합 PSNR 최저값은 opening의 37.19dB였다. 집계에 포함된 프레임 수는 각 원본 전체와 일치했다. 이 비교는 압축 후 영상 샘플의 차이를 측정하며 브라우저의 RGB 변환과 실제 표시 간격은 별도다.

로고의 브라우저 재생을 헤드리스 Chromium에서 정상 속도로 한 차례 측정했다. 게임 시작 버튼을 눌러 저작권 화면에 도달하기까지 chunlogo.mp4의 requestVideoFrameCallback은 153회였고 presentedFrames는 1~153이 연속이었다. mediaTime은 0~5.071733초, 종료 시 getVideoPlaybackQuality는 전체 153, 드롭 0이었다. 콜백의 expectedDisplayTime 간격 중앙값은 33.3ms, 최댓값은 66.7ms였다. 이는 해당 실행의 브라우저 합성기 측정값이며 물리 디스플레이의 출력 시각은 포함하지 않는다.

이름 입력 위치 표시는 EE 0x0011BD24에서 CP932 0x8151(전각 밑줄)의 폭을 조회한다. 셀 폭에서 글자 폭을 뺀 절반을 0 이상으로 제한해 셀 안에서 가운데에 놓고, 0x0011BD4C에서 y에 2를 더한다. 0x0011BD70과 0x0011BDD4에서 이름 문자열보다 먼저 같은 코드를 그린다. 웹판은 추출한 밑줄 글리프(폭 31, 높이 6, 상단 여백 27)를 사용한다. 브라우저에서 빈 이름, 기본 이름 透, 여섯 글자, 여섯 글자에서 한 글자 삭제한 경우 활성 밑줄은 각각 첫째·둘째·여섯째·여섯째 칸에서 관찰했다.

이름 자체와 빈칸 기호도 셀마다 가운데 정렬한다. 0x0011BD90에서 이름 글자의 폭을 조회하고 0x0011BDA4–0x0011BDC0에서 셀 폭과의 차이를 2로 나눠 음수이면 0으로 제한한 뒤 x에 더한다. 빈칸은 0x0011BE20–0x0011BE70에서 CP932 0x8196(＊)에 같은 수식을 적용한다. 브라우저 렌더러에 이름 いく１을 전달하면 세 글자의 시작 x는 355,392,424이고 뒤 세 빈칸은 453,485,517이다.

키보드 셀 렌더러도 0x0011BBB8–0x0011BC30에서 셀 폭과 글자 폭 차이의 절반(음수는 0)을 x에 더한다. 원본 주인공 입력 캡처에서 첫 키보드 행의 앞 9글자와 그룹 표지 11글자를 각각 대조했다. 셀 원점을 x=80 및 144, 간격을 32로 두면 20글자 모두 가로 최적 정렬 위치가 이 정수 공식과 일치했다. 수정 후 실제 새 게임을 통해 얻은 브라우저 캔버스와 PS2 활성 영역의 회색조 상관은 키보드 첫 행(80,119,480,32) 0.942, 그룹 띠 내부(144,74,352,32) 0.904였다.

이름 확인 첫 줄의 시작점은 이름 길이를 읽기 전에 설정된다. 기본 주인공 경로 0x0011D838과 여자친구 경로 0x0011D8C0은 각각 (112,144), (48,144)를 0x0016E9F0에 넘긴다. 고정 접두문을 출력한 뒤에야 0x0010C940(인덱스 0 또는 1)으로 입력 이름을 읽고 이어서 그린다. 0x0011A160은 인자 객체의 첫 워드가 비영인지 반환한다. 비영 분기에서는 두 인물 모두 (128,144)에서 접두문 男性の名前は 또는 女性の名前は를 쓴다. 이 별도 모드의 활성화 조건은 미확인이다. 웹 도입부의 x=112/48은 기본 경로와 일치하며 웹의 y=143은 앞서 캡처로 보정한 그리기 좌표다.

이름 편집기의 문자 도달성을 검사했다. 각 그룹 초기 위치에서 실제 NameEditor.move에 상하좌우를 넣고 (행, 열, 선호 열, 스크롤)을 상태로 너비 우선 탐색했다. 11개 그룹에서 10,373개 상태를 방문했고, 유효한 1,967개 셀 전부를 화면 안에서 선택하고 NameEditor.add로 해당 문자를 입력했다. 중복을 제거한 문자는 1,731개다. 웹 폰트 색인에 없는 선택 문자는 전각 공백 U+3000 하나였다. 이 결과는 웹 탐색 로직의 도달성을 검증하며 모든 방향 전이가 PS2와 일치하는지 또는 원본의 공백 출력 폭이 얼마인지는 별도 검증 대상이다.

SLPS_251.32의 문자열 폭 계산 루프에서 0x0016F5E4는 문자 코드가 0x8140(U+3000)이면 0x0016F628로 분기한다. 일반 문자는 0x0016F600에서 글리프를 조회하지만, 공백 경로는 객체의 메서드 테이블 +0x18 항목을 통해 0x0016F640에서 간접 호출한다. 0x0016F654–0x0016F65C는 그 반환값에 현재 항목의 별도 정수 값을 더해 스택 배열에 저장한다. 0x0016F670–0x0016F680은 그 배열의 첫 값을 누적 폭에 더해 한도와 비교한다. 따라서 글리프 색인의 누락만으로 전각 공백의 폭을 정할 수 없다. 해당 메서드의 반환값과 이름 확인 화면에서의 실제 이동 폭은 미확인이다.

Font, FontNormal, FontRuby의 ELF 가상 함수 테이블은 각각 0x218E00, 0x218E40, 0x218E80에 있으며 +0x1C에 같은 함수 0x16C520을 둔다. 이 함수는 객체 +0x10 필드를 반환한다. 설정 함수 0x16C528은 입력 0이면 0x1703E8에서 로드된 폰트 헤더 +0x10의 32비트 기본값을 읽고, 0xFF이면 기존 필드를 보존한다. Special Box의 SCENARIO/sn4.fnt 헤더 +0x10은 33이다. 파일 기준으로 +0x18은 그룹 수 47이고, 첫 그룹의 +0x0C(파일 +0x28)는 글리프 수 2874이다. 0x1701B8의 중첩 루프가 이 두 필드를 사용하고 각 12바이트 엔트리의 비트맵 오프셋을 재배치한다. 33은 파일의 기본값이며 이름 확인 화면에서 설정 함수를 어떤 인자로 호출하는지는 별도 추적 대상이다.

두 이름 입력 직전의 연출도 디스크에서 대조했다. scenario.sn4의 my01_0047과 my01_0062는 각각 my0002b_00, my0002d_00를 지정한다. scene_pk.spk의 ScenePack 시작은 0x615C8, 연출 스트림 시작은 0x72110이다. 두 엔트리의 상대 오프셋은 0x107과 0x1CF이고 다음 엔트리까지 각각 100바이트다. 두 명령열은 바이트 단위로 동일하며 k1a001.ogg와 my0645.ipu를 포함한다. 따라서 웹 이름 화면에서 두 인물 모두 같은 펜션 배경을 사용하는 것은 원본 데이터와 일치한다. 이 비교로 재생 시점이나 눈 입자의 위치까지 검증되지는 않는다.

음원 주석은 SLPS_251.32의 0x001C3104–0x001C3118에서 0x00225A08의 문자열 L=와 2바이트 비교한다. 일치하면 0x001C3130에서 주석의 세 번째 바이트부터 0x001F3A88로 전달한다. 이 함수는 0x001F3A94의 호출 지연 슬롯에서 기수 10을 지정하고 결과 하위 32비트를 부호 확장한다. 0x001C3138은 이 값을 객체 +0x30에 64비트로 저장한다. ffprobe로 확인한 이름 입력곡 k1a001.ogg의 L 값은 1017889, 타이틀곡 k2t002.ogg는 475399이다. 이름 입력곡은 원본 SOUND/VORBIS 파일과 준비된 웹 파일이 2,024,879바이트 전체에서 일치한다(SHA-256 4f04f125d115941ce034ee2f406a24edff9279eff695bcf97e1ce8758d028bcb). 저장값을 재생 위치로 적용하는 시점과 단위는 미확인이다.

재생 작업 루프의 0x001C1818은 출력 버퍼 채우기 함수 0x001C23F0을 호출한다. 반환값이 비영이면 건너뛰고 0이면 0x001C1828에서 0x001C24A8을 호출한다. 이 래퍼는 디코더 주소에 8을 더한 뒤 0x001CB278로 점프한다. 현재 스트림의 주석 +0x30이 음수면 실패하고, 그 밖에는 0x001CB2AC에서 값을 그대로 0x001CADE0에 넘긴다. 이 함수는 0x001CB00C–0x001CB04C에서 가용 PCM 프레임과 남은 목표 프레임 중 작은 수만큼 소비한다. 따라서 48 kHz 이름 입력곡의 재탐색 위치는 1017889/48000초, 타이틀곡은 475399/48000초다. 채우기 함수는 0x001C2410 및 0x001C241C에서도 0을 돌려줄 수 있어 0 반환만으로 모든 호출이 곡 끝임을 단정할 수 없다.

Special Box ISO의 SYSTEM/chunlogo.pss, opening.pss, pre_dv.pss와 웹 배포 폴더의 동명 MP4를 ffprobe -select_streams v:0 -count_frames로 각각 끝까지 디코딩했다. 모두 640×448이며 로고는 양쪽 153프레임(30000/1001 fps), 오프닝은 3642프레임(30000/1001 fps), 시연 영상 pre_dv는 5835프레임(30 fps)이었다. 이는 전체 프레임 수와 스트림 표기 재생률의 비교이며 각 프레임의 내용이나 표시 시각을 개별 대조한 결과는 아니다.

위 세 영상에서 ffprobe -select_streams v:0 -show_frames -show_entries frame=best_effort_timestamp:stream=time_base -of json으로 디코더의 프레임별 타임스탬프와 스트림의 시간 단위를 읽었다. 각 파일의 첫 프레임 값을 빼고 time_base를 유리수로 곱한 뒤 표시 순서대로 대조했다. 로고 153개, 오프닝 3642개, 시연 5835개 모두 시각이 존재했고 원본 PSS와 웹 MP4 간 상대 표시 시각 차이는 9630개 전부 정확히 0초였다. 디코더 기준의 영상 내부 시간축을 검증한 값이며 오디오 동기나 브라우저 장면 전환 지연은 포함하지 않는다.

음성 동기는 PSS의 첫 오디오 PTS에서 첫 영상 표시 시각을 뺀 값과 MP4 오디오 시작 시각을 보정해 비교했다. 원본 왼쪽 PCM 채널의 20%, 50%, 80% 지점에서 0.5초씩 취하고, MP4 AAC를 PCM으로 디코딩해 예상 위치 ±1/6초를 검색했다. 세 영상 아홉 지점 모두 예상 위치에서 파형 상관계수가 0.9957 이상이었다. pre_dv의 20%에서는 정규화 없는 내적이 약 72ms 앞을 골랐지만 각 후보 구간 에너지로 정규화하자 예상 위치(오차 0샘플)가 최대였고 상관계수는 0.99979였다. 파일 디코딩 기준이며 실제 재생 장치 지연은 측정하지 않았다.

타이틀 영상은 SYSTEM/title.mmv 두 레코드를 각각 잘라 ffprobe의 frame.duration에 stream.time_base를 곱해 웹 MP4와 순번별 비교했다. 진입 영상은 양쪽 121프레임(총 121/30초), 대기 영상은 양쪽 241프레임(총 241/30초)이다. 모든 프레임 길이는 정확히 1/30초였다. 원본 MPEG-2 스트림에는 각각 best_effort_timestamp가 없는 프레임이 하나씩 있어 이 결과는 프레임 길이 비교로 한정한다.

타이틀의 입력 폴링 순서도 확인했다. MMV/M2V 선택 뒤 0x001084A8–0x001084CC의 외부 루프는 미디어 상태를 조회해 저장하고 0x00154480 호출 뒤 0x00108818에 모드 1을 전달한다. 이 모드에서는 0x00108860–0x00108864가 첫 입력 마스크를 그대로 복사한다. 이후 0x001084C0에서 0x00108CA8을 호출해 0이면 루프를 반복한다. 메뉴 갱신 함수 0x001088C0은 0x001088CC에서 입력값을 읽고 0x001088D4에서 메뉴 처리기로 넘긴다. 외부 루프에서 버튼을 읽는 시점과 메뉴 상태에서 선택을 적용하는 시점은 구별해야 한다. 최초 선택 가능 프레임은 미확인이다.

타이틀 로더 0x00108710은 0x0010876C에서 미디어 상태 1을 기다리고, 0x00108774에서 0x0019A720을 호출한 뒤 0x00108794에서 상태 2를 기다린다. 0x0019A720은 미디어 객체 +0x50C의 비트 0을 세운다. 상태 1의 처리기 0x0019ACA8은 이 비트가 켜지면 0x0019AD18에서 0x0019A7A0을 호출한다. 이 함수는 +0x4B8 값 0/1/2/3을 각각 0x0019B660/0x0019BDB0/0x0019CE40/0x0019DF50으로 분기하고 그 밖의 값에는 0을 반환한다. 성공 경로는 0x0019AD4C에서 객체 +0x4B0에 2를 쓴다. 이 공통 분기에는 영상 프레임 번호와의 비교가 없어 메뉴 입력 시작 프레임을 특정하려면 타이틀이 선택한 하위 처리기를 확인해야 한다.

형식 표 0x00209A70의 처음 네 문자열은 순서대로 ipu, m2v, mmv, pss다. 0x0019A064–0x0019A080에서 이름과 비교한 인덱스 s1을 0x0019A158에서 객체 +0x4BC에 저장하며 0x0019AC6C–0x0019AC78에서 +0x4B8로 옮긴다. 위 분기표에 따라 정상 진입 SYSTEM/title.mmv는 인덱스 2의 0x0019CE40, 스킵 진입 SYSTEM/title.m2v는 인덱스 1의 0x0019BDB0을 사용한다.

MMV 준비 함수 0x0019CE40은 객체 +0x1F8이 3이면 0을 반환하고, 그 밖에는 +0x1FC를 0으로 쓰고 1을 반환한다. M2V의 0x0019BDB0도 +0x1E8/+0x1EC로 같은 처리를 한다. 실제 메뉴 입력에는 별도의 수치 조건이 있다. 0x00108CD8은 gp−0x78E4(현재값)를 128, gp−0x78E0(목표값)를 0으로 초기화한다. 0x00108B10–0x00108B24는 현재값이 목표값보다 작거나 65 이상이면 버튼 분기를 건너뛴다. 초기 목표가 유지되는 동안 입력 처리가 가능해지는 경계는 현재값 64다. 0x00108D40–0x00108D8C에서 gp−0x78CC가 0인 갱신에만 현재값이 gp−0x78D0의 간격으로 목표를 향해 움직인다. 이 조건을 만족하는 시각과 최초 입력 가능 프레임은 구분해야 한다.

입력 허용 경계에 필요한 갱신 횟수도 계산할 수 있다. 메뉴 초기화 루틴 0x00108A60은 0x00108AA4–0x00108AAC에서 gp−0x78D0에 2를 쓴다. 0x00108CF8은 gp−0x78CC를 0으로 만들어 값 갱신을 허용하고, 0x00108D00은 1로 만들어 중지한다. 초기값 128, 목표 0, 간격 2가 유지될 때 0x00108D10의 활성 갱신 31회 뒤 값은 66이고 32회 뒤 64다. 따라서 32번째 감소가 반영된 뒤의 입력 검사부터 수치 조건을 통과한다. 이는 갱신 횟수이며 첫 영상 프레임 기준 시각은 아직 측정하지 않았다.

### SN4 직접 입력 명령

`SpecialInputChecks.java`로 입력 명령의 EE Execute 경로를 확인했다. `0x7A`(0x0012FE10), `0x7E`(0x00130A18), `0x7F`(0x00130F80), `0x82`(0x00131D08 → 0x00131A78)는 첫 실행에서 입력 UI를 만들고 1을 반환한다. 입력 완료 뒤에는 `0x00115788`로 선택 인덱스를 얻어 packed label 배열의 대응 라벨로 분기한다. 웹 VM도 같은 지점에서 `special` 이벤트로 정지하고, 클릭 맵·4열 패널·망상 패널·15×6 범인 이름판의 결과를 받은 뒤 선택 라벨에서 재개한다. 패널의 `0x4E` 항목은 선택 대상에서 빼고 별도 packed fallback 라벨을 취소 경로로 쓴다.

`0x1F`의 Execute는 0x00133538이며, 초기화 함수 0x00118F78이 변수 230(0xE6)을 0으로 만든다. operand 11은 마지막 슬롯의 0부터 센 번호이므로 입력 수는 12회다. `×△×□×△△□×△□×`과 일치할 때만 웹 VM도 변수 230을 1로 만들고, 그 밖에는 0인 채 다음 명령으로 진행한다.

투시 입력 `0x7A`는 원본 EE 커서 확정 좌표를 재생해 얻은 952개 `(x, y, region)` 측정점을 사용한다. 측정된 모든 좌표는 원본의 10개 분기와 일치하며, 0번 영역은 `(133..135, 220)` 세 점에만 존재한다. 측정되지 않은 웹 터치·키보드 좌표는 가장 가까운 측정점의 영역으로 보간하되, 0번 영역만은 이 세 좌표에서만 선택되도록 제한한다.

타이틀 메뉴 입력 검사에 쓰는 gp−0x78E4는 렌더러에서도 읽힌다. 메뉴 항목 반복 전 0x00108F70–0x00108FA4는 세 워드 (0x42, 0x44, 현재값)를 구성하고, 반복 뒤 0x0010913C–0x00109160은 (0x42, 0x64, 현재값)를 구성한다. 0x00139C90–0x00139CBC는 첫 워드를 출력 패킷 +8, 둘째를 +0, 셋째를 +4에 쓴다. 따라서 현재값이 두 패킷 모두의 64비트 데이터 상위 워드로 들어가는 것을 확인했다. 개별 픽셀 밝기가 이 값과 선형으로 변하는지는 이 패킷만으로 판정할 수 없다.

## 저장과 기기 연결

- 공통 저장소(`shared/save`, 설계 `docs/save/README.md`)를 쓴다. 허브가 `/shared/save/`를 내줄 때만 켜지고, 따로 열면 이 브라우저에만 저장한다.
- 원작의 메모리 카드 단위를 슬롯으로 옮겼다(`save.js`). 바이너리 모양은 옮기지 않았다.

| 슬롯 | 원작 | 내용 |
|---|---|---|
| `mc0-data01`, `mc1-data01` | 카드의 `BISLPS-25135DATA01`(note01/02 .dat·.dhd) | 이름, 변수 300개, 다시 시작할 SN4 위치, 배경·음악 |
| `mc0-system`, `mc1-system` | 카드의 `SYSTEM/system%02d.dat`(엔딩 처리 `0x123924` → `0x105408`) | 회차를 넘는 변수 300개 |
| `suspend` | 없음(웹 전용) | 페이지를 떠날 때의 위치 |

- 자동 저장을 켜면 선택지와 입력 화면마다 그 카드의 이야기 저장을 쓴다. つづきから는 거기서 다시 시작한다. 원작이 note를 쓰는 정확한 시점은 아직 원본과 대조하지 않았다.
