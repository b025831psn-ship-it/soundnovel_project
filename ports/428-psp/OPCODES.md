# 428 PSP (ULJS-00219 v1.01) 스크립트 VM 메모

기준: EBOOT 복호화본 SHA-256 `194a2dcb…3dce`, 시나리오 `to.sns` (원문 = 암호문 − `CSD-CSCNV:01.82\0` 반복, 바이트 뺄셈).

## 실행 구조
- 한 스텝: `0x0886F224` — 스트림에서 op 1바이트를 읽고 `0x08898398`에서 디스패치.
- 핸들러 테이블: `0x089C090C`, 8바이트 × 193개 (op 0x00–0xC0).
- 스트림 읽기: `0x0887C510`(n바이트 빅엔디언), `0x0887C610`(건너뛰기), `0x0887C670`(문자열).
- 형식: 거의 모든 op = `op, len, payload[len]`. 핸들러는 맨 앞에서 len 바이트를 건너뛰고 인자를 읽는다.
- 예외: `01` 본문(Shift-JIS, 다음 `02` 바이트 직전까지), `02` 본문 끝, `1C` 루비 시작(이어지는 `01…02` 구간이 글자별 읽기), `1D` 루비 본문 시작. 셋 다 len 없음.
- 34개 스크립트 모두 코드 시작(스크립트 헤더 +0x430 u32)부터 끝까지 어긋남 없이 해석됨.

## 라벨
- `56 len 01 name\0` 라벨. 라벨 표 레코드 `u16 reclen, "No", u32 off, name\0` — off = 라벨 op 끝 − 코드 시작.
- `59 len 01 name\0` 점프(추정). `52`/`57` 내부 라벨 `__1_n` 참조(분기·서브루틴 추정). `53/54/55` 선택지(`…_SEL_…` 이름).

## 자원 참조 (확인)
자원은 이름이 아니라 **현재 장 CPK의 파일 ID**로 가리킨다 (k01 스크립트 ↔ k01.cpk TOC ID). 상위 비트 0x8000은 반복음(env/_lp) 표시.
| op | 의미 | 근거 |
|---|---|---|
| 44 | 사진 표시 `00 id …` | id 1 = black.gim, 6/8/9 = k01a_0010_c03/c03a/c03b |
| 7A | 효과음 재생 `id, …` | id 3 = se_k01a_0010_c_sh, 0x8005 = se_k01a_0010_b_lp |
| 7B | 효과음 정지 | 0x8005 정지 |
| 91 | 환경음 재생 | 0x8004 = env_c_shibuya_sc_01_lp |
| 92 / 93 | BGM 재생(볼륨 0x32) / 페이드 | id 7 = bgm_m08 |
| 9C–9E | 영상 `9C id(u16, 0x4000=소리 전용 _snd) 볼륨(u16) 1 1` 재생, `9E id` 끝날 때까지 대기, `9D id` 정지 | id 0x0b = k01a_0010_m02.pmf. 영상은 다음 그림이 되어 걸려 있는 전환(63…64 65)으로 들어온다 |

## 빈도 높은 op (추정, 핸들러 확인 전)
- `1B` 줄 끝 대기, `1E` 다음 줄, `1F` 페이지 끝, `2D 00 00 00 nn` nn 프레임 대기, `22` 장면 시작 플래그, `23 n`/`25` 글자창 열기·닫기(n=창 종류), `63` 화면 전환, `64/65` 전환 실행·대기, `66/67/69` 사진 카메라(이동·확대 키프레임), `80` 카메라 초기값(float), `0C/03/05` 페이드 시간, `0F 08` 글자 속도, `6C` TIPS 등록, `5A` 플래그 이름 참조.

## 라벨 표 (확인, 2026-11-25)
- 스크립트 헤더: +0x000 이름, +0x400–0x42F 해시 버킷, +0x430 u32 코드 시작, +0x434부터 코드 시작까지 레코드.
- 레코드 `[u16 체인][태그 'No'=장면 라벨 | 0xFFFF=내부 분기 __<스크립트번호>_<n>][u32 코드 시작 기준 오프셋][이름\0, 4바이트 정렬]`.
- 내부 분기 라벨(1,804개)은 코드에 0x56이 없고 위치만 가리킨다. 슬롯 번호 = 스크립트 번호(to.sns 순서).

## 제어 명령 (핸들러 확인)
- `57` IF (0x08898748): s16 n. n ≥ 0이면 `var=n, cmp u8, imm u16`. n < 0이면 항 −n개, 항 사이 바이트 0=OR 1=AND(이후 항에 적용, 왼쪽부터 누적, 초깃값 0), 항 태그 0x57=변수·상수, 0x58=변수·변수. 끝에 `slot u8, label`. **조건이 거짓이면** goto.
- `58` 변수·변수 IF 한 항, 거짓이면 goto.
- goto 0x0887C21C(ctx, slot, label): 슬롯 스크립트의 해시로 라벨 검색 → 현재 스크립트·pc 교체. '_'로 시작하지 않는 라벨은 진행 기록(ctx+0x27a8).
- `00` 길이만큼 건너뛰는 빈 명령(0x088982D8).
- `AC` 장면 끝: 상태 플래그에 따라 게임 모드(0x0887CB38 인자 0x1f/0x20/0x3b/9)로 넘김. 다음 장면은 스크립트가 아니라 엔진의 타임차트(캐릭터 전환·LOCK) 쪽이 고른다 → 별도 구현 필요.

## 표시 명령 (임시 해석, 시제품에서 사용)
- 인자는 len 바이트 뒤부터 빅엔디언. 자원 id는 u16(0x8000 = 반복음).
- `03/05 u32 n` n프레임 동안 화면 어둡게(0x0886A648 페이드 층, 0→128), `07/09 u32 n` 밝게(128→0), `04/08` 즉시 해제, `06/0A` 즉시 최대. 05/09는 색을 0으로 먼저 설정. (핸들러 0x088A1008 점프표 0x089ABBF4)
- `23 n` 본문 묶음 시작(n=2 아래 창, 3 화면 중앙 서술), `25` 묶음 끝, `1B` 입력 대기, `1E` 줄바꿈, `1F` 입력 대기 후 페이지 지움, `1C` 루비 읽기 / `1D` 루비 본문.
- `2D u32 n` n프레임 대기. `44 u16 id, u8, u8` 다음 사진. `63 type u8 u8 [u16 프레임]` 전환 설정, `64 01` 전환 시작, `65 01` 전환 끝까지 대기.
- `7A u16 id, u16 볼륨, …, (+8) u16 페이드인` 효과음, `7B u16 id, u16 페이드` 정지, `91` 환경음, `90` 음량 변화, `92 u16 id, u16 볼륨` BGM, `93` BGM 페이드아웃.
- 글꼴 글리프 머리 0x24바이트 = u16 LE ×18: 가로 [진행폭, em, bx, by, bw, bh], 전각 같은 6개, 세로 6개. 본문 = 글꼴 0 크기 50(2,304자), 루비 = 글꼴 0 크기 22.

## 글자 표시 (원작 캡처로 확인, K01A_0010)
- `1B` 줄 대기: 다음 줄 맨 앞(x=51, 줄 위+27)에 위아래로 뒤집히는 회색 ▶(10×17). 글자가 하나도 없는 페이지에서는 기다리지 않는다. `17`…`18` 가운데 정렬 구간 안에서는 기다리지 않고 줄만 바꾼다.
- `1F` 페이지 대기: 마지막 글자 뒤 약 4px에 펼친 책 아이콘(15×13), 누르면 페이지를 지운다.
- `17`/`18` 가운데 정렬 시작/끝: 줄마다 x=240 기준 가운데, 페이지 전체는 y≈116 기준(한 줄이면 위 108, 줄이 늘 때마다 13.5 위로).
- `43 1 0` 말줄임 한 칸(…), `2B n` 대시 n칸(―). 글꼴에 없는 문자라 직접 그린다. `0F n` 짧은 멈춤(추정).
- 글자 진행폭 = 글리프 진행값 × 0.375 + 0.7 (가로 폭이 원작과 픽셀 단위로 일치, 줄바꿈 위치도 일치).
- 루비는 바탕 글자 폭에 고르게 나눠 각 칸 가운데, 줄 위 8px.
- `03 n` 어둡게는 검정까지(n=0이면 즉시).
- 남은 차이: 영상이 원작보다 밝고 차갑다(원작은 따뜻하고 어두움, 원인 미확인), 루비 글꼴 크기, 글자 세로 1~2px.

## 사진 속성 키프레임 (원작 캡처로 확인)
- `66`/`67 <속성> <층> 00 <사진 id u16> <값 개수 n> <u16 × n>`: 66은 첫 키프레임, 67은 다음 키프레임. `69 <속성> <층> 00 <id>`로 해제.
- 속성 8 (n=6) = `[프레임, x1, y1, x2, y2, 가속]`, 화면에 보일 원본 사각형. 단위는 1280×720 = 사진 464×256픽셀(보통 전체 화면 사진 크기). 카메라용 사진은 752×496. K01A_0010 c04 끝 키프레임과 상관 0.98로 일치.
- 속성 24 (n=3) = `[프레임, 값 0–255, 가속]`, 불투명도로 보임(미구현). 19·22·26·12 등은 미해석.
- 원작 화면의 사진·영상은 디코딩한 파일보다 어둡고 따뜻하다: R×0.73, G×0.69, B×0.65 (c04 비교). 원인 미확인, 플레이어는 곱하기 색 rgb(186,176,166)로 맞춤.
- `63 종류 a1 a2 [u16 × n]` 전환. 실행 파일 표 0x089CAAB4(종류마다 [초기화 함수, u16 개수])와 종류별 상태 함수로 확인:
  - 1: 새 사진을 바로 깔고, 화면 전체 검은 사각형(0x0888CF40, 1280×720 rgba(0,0,0,a))의 a를 1→0 (검은 화면에서 밝아짐). 쓰임 685 사진→사진, 671 검정→사진.
  - 2: 옛 사진 위 검은 사각형 a를 0→1, 끝나면 새 사진 (검게 사라짐). 쓰임 801 사진→검정.
  - 3: 두 층의 섞임 비율(0x0888ABD0, 층 +0x4BC)을 0→1, 프레임 절반에서 중간값을 지나는 두 구간 (겹쳐 바뀜). 쓰임 3,123 사진→사진.
  - 4: u16 7개 [?, ?, 프레임, R, G, B, ?]. 색(대개 흰색) 번쩍임으로 임시 구현(가운데에서 사진 교체). 원작 대조 전.
  - 11: 즉시(u16 없음). 12: u16 4개, 마스크 사진을 쓰는 와이프로 보임, 원작 대조 전이라 겹쳐 바뀜으로 대신함.
- 사진 층: `44 id(u16) 층 b`. 층 1(드물게 0)은 전환으로 들어오는 본 사진, 층 2~8은 위에 겹치는 사진. `6A 층` 보이기, `6B 층` 지우기, `68 속성 층 00 id` 그 속성 키프레임이 끝날 때까지 대기, `69 속성 층 00 id` 그 속성 키프레임 해제.
- 속성 14 (n=6) `[프레임, x1, y1, x2, y2, 가속]` 겹친 사진의 화면 위치(1280×720 단위, K08A_0010_1200에서 사진 네 장이 6000프레임 동안 천천히 흐름). 속성 24 (n=3) `[프레임, 불투명도 0~255, 가속]`. 겹친 사진의 크기 배율은 본 사진과 같다고 가정(464×256 사진 픽셀 = 480×272 화면). 67의 프레임 수는 지금부터 센다(K08A_0010_1230: 6000프레임 이동 중에 15프레임 이동을 보내고 68로 기다림). 속성 14의 정확한 뜻(위치·시차 스크롤)은 원작 대조 전.

## Zapping (JUMP) and hour blocks

- `70` starts a JUMP keyword (the red word in the text). Payload: `00`, one condition in the `57` term format
  (usually "the target character waits at its CONTINUE", e.g. var 600 == 1), slot, target label, u16 (?), u16 var.
  While the condition holds the player can JUMP: the var is set to 1 and play moves to the target label (mostly the
  other character's `_CONTINUE_CHECK`, which tests that var). `72` ends the keyword. All 77 keywords decode cleanly.
- The ZAP node of the character who jumped (`..._ZAP` label before the keyword, to.flo kind 3) stays on the time
  chart, so the player can come back there later.
- `6C ... 'TIP_xxx'` / `6E` mark a TIPS keyword (not implemented yet).
- Var 14 is never written by scripts: the engine raises it (0x08876338) when the current hour block is complete.
  Block tables in the EBOOT (columns K A O M F J T S C E): first scene per character 0x089BDD04, block-end
  `_CONTINUE_CHECK` per character 0x089BE2E4, block-end vars (300 + ...) 0x089AB654, story var ranges 0x089BFACC.
  Complete = every block-end var set, every story var in the range set, every block-end label passed.
  `TOP_FLAG_xxA_GOON_CHECK` then sees var 14 > block and the `_CONTINUE_CHECK` jumps into the next block.
  Implemented in `engine/game.js` (BLOCKS); `test/game-search.mjs` plays 10:00 through to 11:00 headless.
